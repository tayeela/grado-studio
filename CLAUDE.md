# ГРАДО Студия — память проекта

> Этот файл читается автоматически в начале КАЖДОЙ сессии внутри `~/grado-studio` (в любом чате/аккаунте).
> Здесь — только то, что нужно знать ДО первого действия. Историю версий и разбор конкретных
> решений смотри в `docs/session-log-archive.md` (детальный лог с диагнозами до 2026-07-14),
> `docs/roadmap.md`, `docs/fixes-geometry-layout.md`, `git log --oneline`.

## Что это
Единая среда градпроектирования (ГИС + точное 2D-черчение + вёрстка альбомов) над одной моделью
данных, для этапов анализ существующего положения → АГК → ППТ. Растёт из QGIS-плагина **GRADO**
([../grado] — отдельный проект, не путать) в standalone-продукт.

**Юзер:** градостроитель/архитектор, НЕ программист, уверенно работает в QGIS. macOS.
Общение только по-русски, без эмодзи, прямые ответы без лирики. Не пиши код-жаргон в ответах —
объясняй результат в терминах того, что он увидит на экране.

## Рабочая программа (то, что юзер реально открывает и трогает)
`apps/studio` — браузерная студия черчения, referens UX rayon.design.
```sh
python3 apps/studio/server.py        # http://localhost:8643
```
Превью-конфиг **studio** (порт 8643) прописан и в `~/.claude/launch.json`, и в `.claude/launch.json`
репо — используй `preview_start "studio"`. **Backend-изменения (server.py/studio_core.py/styles/*.json)
требуют restart превью** (нет хот-релоада); фронтенд (app.js/**app-transform.js**/index.html/
style.css/tokens.css) подхватывается обычным reload. Скрипты в index.html грузятся по порядку в
общем global-scope: `canvas-theme.js` → `app-transform.js` → `app-snap.js` → `app-data.js` →
`app-style-ui.js` → `app-attr.js` → `app.js` → **`app-import.js`** → `collab.js`. Модули ПЕРЕД app.js
(их функции нужны на init), а `app-import.js` — ПОСЛЕ (в нём top-level execs: setInterval/on-биндинги,
которым нужны on/state из app.js). P0-разрез монолита — детали в `docs/session-log-archive.md`.

## ЖЕЛЕЗНЫЕ ПРАВИЛА

1. **Проект юзера в браузере — необратимо ценные данные. Никогда не тестируй live на нём.**
   Автосейв дублирует localStorage → диск (`.autosave.json`) с дебаунсом; при гонке чужая правка
   может затереться. Для любых экспериментов с состоянием (snapping, drag, group-edit и т.п.):
   сохрани `state.features` в переменную, работай без `persist`/без `mouseup` (mouseup = запись),
   восстанови. Если всё же понадобится восстановление реального проекта — инжект пристинного
   base64 НАПРЯМУЮ в localStorage (`localStorage.setItem("grado_studio_v1", decodeURIComponent(escape(atob(b64))))`
   + reload) обгоняет гонку автосейва; просто `removeItem`+reload — НЕ обгоняет и может проиграть.
2. **Стили ЛГР (`core/render/grado_render/styles/moscow_lgr.json`) — генерируются, не редактируются
   руками.** Источник — `tools/gen_moscow_lgr.py` (STROKE_QML/DASH_QML/HATCH_QML/MARKERS/OUTWARD и
   т.д.). Правка стиля/маркера/цвета = правка словаря в скрипте → перегенерировать JSON.
3. **Эталон vs QML — юзер выбрал QML.** Есть два стандарта условных знаков ЛГР: приказ
   Москомархитектуры №65 (эталон, `docs/`) и рабочие QML-файлы Москвы (реальные слои). По решению
   юзера («Всё ровно по QML») линии/зоны/маркеры синхронизированы с QML, а не с эталоном —
   за исключением точечных правок по факту (ООЗТ-47 красные линия+треугольники, водоохранная-16
   галки внутрь, ЛЗП-49 без маркера — из явных правок юзера, не из QML/эталона напрямую).
4. **canvas в flex-контейнере — всегда `flex-basis 0` + обёртка `position:absolute`.** Иначе
   `canvas.width` участвует в auto flex-базе → ResizeObserver зацикливается → холст раздувается
   до тысяч px («белый экран», особенно в Safari).
5. **Ошибки сервера (`send_error` и т.п.) — строго ASCII.** Python.org сборка на macOS не даёт
   latin-1-safe кодирование кириллицы в HTTP-заголовках; кириллица в error-message каскадно роняла
   сам error-handler (пустой ответ, обрыв соединения).
6. **Внешние HTTPS-запросы из Python.org build urllib** падают `CERTIFICATE_VERIFY_FAILED`
   (нет доступа к системным CA) — нужен явный `SSLContext(cafile=certifi.where())`.
7. **Слой (`layer_id`) — не то же самое, что вид объекта (`kind`).** Любая маршрутизация
   (`addFeature`, стили, ТЭП-мост) должна идти по активному/явному `layer_id`, никогда по
   первому слою данного `kind` — иначе второй слой того же вида молча теряет объекты
   (класс бага уже дважды пойман: `state.activeLayerId` и GISOGD-роутинг).
8. Тесты (`unittest`) — обязательный гейт перед коммитом:
   ```sh
   PYTHONPATH="apps/studio:apps/wizard:core/render:core/geom:core/layout:core/compute:core/model:core/reactive:core/connectors" \
     python3 -m unittest discover -s <модуль/tests> -p "test_*.py"
   ```

### Интерфейс
- **Новый UI (`index.html`) — основной**, кат-овер завершён: сгруппированный левый тулбар,
  контекстная правая панель (Свойства → Слои → ТЭП, сворачиваемые карточки), меню
  Данные▾/Проект▾/Выпуск▾, командная палитра ⌘K, поповеры Подложка/Сетка/Источники.
  `index-classic.html` — рабочий фолбэк на старом `style.css`. `app.js`/движок в редизайне не
  менялся — только CSS-перестиль (`redesign/{shell,studio2}.css`) сгенерированной разметки.
- **Все диалоги движка ревизированы и в едином виде** (Библиотека знаков, Типы слоёв, Варианты,
  Горячие клавиши, Управление/Калькулятор полей, Оформление слоя, Данные по области, Состав
  альбома, таблица атрибутов, подтверждения) — единая **inset-система окон** (14px внутренний
  отступ, поля/кнопки 36px, без полос от края до края); обязательный процесс `design-qa.md`
  на UI-правки (эталон-макет vs скриншот реализации, чек-лист, verdict passed/failed).
- **Доступность (`redesign/a11y.js`):** `role=dialog`, автофокус диалога, Tab-trap, Escape,
  возврат фокуса; меню/⌘K получили ARIA-роли и `aria-expanded`; `⌘`/`Ctrl+` в подсказках
  подставляется по ОС (Windows не показывает Mac-символы).
- Обе темы (light/dark), reduced-motion/reduced-transparency/contrast — поддержаны.

### Данные и импорт
- **«Данные по области»** — прямая выгрузка без бриджа/расширения: **НСПД/Росреестр** (intersects
  API, без авторизации), **OSM/Overpass** (дороги/здания/землепользование/вода/адм.границы),
  **рельеф** (горизонтали из AWS Terrain Tiles/SRTM, marching squares), **Sentinel-2 cloudless**
  подложка (EOX, без ключа). Дедупликация повторной выгрузки по `srcKey` (не переживает
  `.grado` round-trip — известное ограничение).
- **ГИС ОГД Москвы**: портал за SSO недоступен напрямую → ZIP/ссылка/папка/одиночный GeoJSON,
  автоподхват из `~/Downloads`. SHP читается **pure-Python без GDAL/QGIS** (`shp_reader.py` +
  `crs.msk50_to_wgs84`, сверено с PROJ < 1мм). Ничего не отбрасывается молча (`source.gisogd.other`
  для нераспознанных слоёв, все атрибуты сохраняются).
- **Московские городские слои (`data.mos.ru`) — недоступны из среды** (API требует ключ, домен не
  резолвится/блокируется) — не реализовано, это НЕ баг импорта.

### ТЭП (технико-экономические показатели)
- Считается **ВНУТРИ границы территории разработки** (роль `terr_area`); без границы — честное
  предупреждение «граница не задана», не мусорные цифры по всей карте.
- **Нормативный профиль Москвы** (`core/compute/grado_compute/regulations/moscow_urban_planning.json`,
  реестр НГП-актов 801/945/2150/2151/2152-ПП и др.) подключён в `compute_tep` — вместо жёстких
  эвристических порогов плотности (`>40`/`<10`) даёт предупреждения «требуется сверка» и расчёт
  ДОО/школ по зонам 1/2 (2151-ПП). Описание — `docs/regulations-moscow.md`.
- Редактор пресета/параметров и генерация буферов — в панели (шестерёнка карточки ТЭП / левый
  тулбар), не в `#engine-slots`.

### Подписи объектов (настройка + печать)
- В «Оформлении слоя» (полигональные слои) — секция «Подпись объектов»: поле подписи (включая
  «без подписи»), кегль 6–72px, цвет, семейство шрифта (системный/с засечками/моно).
- **Кегль/цвет/семейство доходят до печати PDF** (не только холст): `Style.label_size`/
  `label_color`/семейство в `style.py`/`scene.py`; собственный PDF-writer динамически встраивает
  нужные TTF по семействам (кроссплатформенный поиск шрифтов — Arial/Georgia/Courier New на
  macOS, DejaVu на Linux, системные аналоги на Windows), SVG-бэкенд тоже учитывает семейство.

### Черчение (CAD)
- Точки/линии/полигоны/дуги (3 точки, hold параметры)/окружности как полноценные CAD-примитивы
  (snap на центр/касательные/квадранты, точные пересечения, drag-edit).
- Trim/Extend/Join (T/E/J), Сопрячь (fillet угла с радиусом), интерактивные Поворот/Масштаб/
  Зеркало (произвольный угол/коэффициент, привязка опоры к вершинам, undo-safe).
- Единая точность округления (координаты 4 знака = 0.1мм, длины/площади через fmtLen/fmtAreaHa).
- Пространственный индекс привязок (грид, `app-snap.js`) — не для всех операций (см. хвосты).

### Надёжность и жизненный цикл проекта
- Автосейв: версионированная оболочка (schema_version, UTC, SHA-256), ротация до 10 копий,
  повреждённый файл не блокирует работу (`.autosave.corrupt.json`), диалог восстановления в
  меню «Проект». Цикл «Новый/Открыть/Сохранить/Выпустить» — атомарный (не дублирует объекты/nextId).
- **Preflight перед выпуском** (`/api/preflight`, DXF/печать/альбом/.grado): проверка слоя,
  геометрии, обязательных атрибутов, дублей ID, границы территории — блокирует выпуск с
  конкретными ID вместо молчаливой потери объектов; предупреждения можно осознанно принять.

### Совместная работа (`webhub.py`/`collab.js`, флаг `--hub`)
- Throttling повторных неудачных логинов, аккаунты/сессии приватны по клиенту, битое хранилище
  не роняет хаб (fail-closed + прунинг), rev/409-конфликт сериализует писателей + 3-way merge
  на клиенте, защита от гонок повторных запросов коллаборации.

## Запуск и платформы
- **macOS:** `ГРАДО Студия.command` (двойной клик) или `.app` (`packaging/py2app_setup.py`).
- **Windows:** `ГРАДО Студия.bat` (двойной клик; нужен Python 3.8+ с «Add to PATH»).
  Windows-лаунчер: детект Python → авто-`certifi`/`Pillow` → `server.py --desktop`; режим ищет
  свободный порт, повторно открывает уже работающую Студию и не теряет перетащенный `.grado`.
  Данные лежат в `%LOCALAPPDATA%\GRADO Studio`, не рядом с исходниками. `.gitattributes` держит
  `.bat`=CRLF, `.command`=LF.
- **Кросс-платформенность кода** (правки для Windows): `ttf.py` — шрифты Windows
  (`%WINDIR%\Fonts\arial|tahoma|segoeui`), иначе PDF-экспорт падал `FontError`; `_tile_jpeg`
  (studio_core) — PNG→JPEG через Pillow (опц., кросс-платформенно) → `sips` (macOS) → деградация
  (OSM-подложка в PDF без Pillow не рендерится, спутник ESRI работает); `find_ogr2ogr` (gisogd) —
  Windows-пути `C:\Program Files\QGIS*\bin\ogr2ogr.exe`. Зависимости: только `certifi` (опц.),
  плюс `Pillow` (опц., OSM-в-PDF на Windows) — см. `requirements.txt`, `docs/INSTALL.md`.
- **Веб-версия совместной работы (флаг `--hub`)** — детали механизма см. «Текущее состояние →
  Совместная работа» выше. Архитектура: `apps/studio/webhub.py` (`Hub`, файловое хранилище `.hub/`,
  users scrypt, invites одноразовые, rev-based sync) + `server.py --hub` (гейт `_hub_gate` на
  `/api/*`) + фронт `web/collab.js` (3-way merge, 409-retry, поллинг 2.5с). БЕЗ `--hub` — локальный
  режим как раньше (HUB=None). **Деплой:** отдельный VPS за reverse-proxy с HTTPS (пароли по HTTP —
  открыто), либо готовый `Dockerfile`/`--cloud` (см. «Дистрибуция» выше, форсит hub-auth). Launch-
  конфиг превью для локального теста: `studio-hub` (8666). Осторожно с мощными endpoint'ами наружу
  (`import-gisogd-path` читает файлы из ~/Downloads — в `--cloud` режиме уже отключено).

## Как юзер обычно ставит задачи
- Даёт файлы-эталоны (PDF приказов, QML, скриншоты) и просит сверить/привести в соответствие —
  сверяй атрибут-в-атрибут, не додумывай.
- Часто отвечает коротко («да», «продолжай», номер варианта) — держи в голове предыдущий вопрос.
- Просит «сделай пригодным для работы» / «понятнее и удобнее» — это открытая директива продолжать
  UX-улучшения без переспрашивания на каждый шаг, но крупный разворот направления — через вопрос
  (AskUserQuestion), а не молча.
- Коммить разрешено (git, ветка main) — коммит на каждый завершённый шаг с версией в сообщении
  (`vX.Y.Z: суть`).


## Правки этой сессии (сверх снимка выше)

- **2026-07-15, v0.9.0-beta.67: одиночный GeoJSON в БРАУЗЕРНОЙ редакции — на LineCode (последний путь веба).**
  При запросе «опубликовать в веб» вскрылось: beta.66 (ручной ZIP) — серверная, а в браузере ZIP ЗАПРЕЩЁН
  (адаптер отдаёт 415), одиночный GeoJSON шёл через `importGeoJson`, который маршрутизировал по ИМЕНИ
