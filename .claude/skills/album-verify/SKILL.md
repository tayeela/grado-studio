# Проверка альбома (до / после)

Цель — доказать картинкой, что изменилось только задуманное. Владелец смотрит вырезки, не текст.

1. Тестовый сервер, не 8650: `preview_start {name:"grado2-t86"}` (8671) или другой из `docs/wiki/files.md`.
   После правки `*.py` — перезапуск сервера, после `web/*.js` — перезагрузка страницы.
2. Копия проекта (не `~/Documents/ГРАДО 2`): `openProject(имя)` дважды. Если менялась сборка или данные — пересобрать
   альбом: `buildAlbum("pptkrt")`, кнопка «Заменить», дождаться конца.
3. Спецификация: `fetch('/api/project?name=_specCHK', {method:'POST', body: JSON.stringify(albumSpec(ALBUM.sheets))})`.
4. Сравнение: `~/.grado2/venv/bin/python tools/album_check.py --spec <папка проектов>/_specCHK.grado2 --name <gol|bez|…>`.
   Код 0 — без отличий, 1 — отличия: открыть `/tmp/grado-album-check/<name>/summary.png` и `report.md`.
   Код 3 — `tools/album_lint.py` (он запускается сам, отчёт — в конце `report.md`) нашёл ошибки оформления: наложенные слова, текст за краем,
   невшитый шрифт, размытые вставки. Их чинят, а не принимают эталоном; каждое предупреждение — объяснить в отчёте.
5. Каждое отличие — намеренное (по задаче) или ошибка. Ошибку — исправить и повторить с шага 1. Лист, который меняли, ещё и пройти по плиткам
   `docs/standards/albums/layout-qa.md` (то, чего компьютер не видит).
6. Две территории, если правка общая: КРТ 3229 (`gol`) и Безобразово-копия (`bez`).
7. Эталон обновлять (`--update`) только после того, как владелец принял результат: он уходит и на GitHub (релиз
   `album-baseline`); нет эталона на диске — берётся оттуда сам.
8. Удалить временные `_spec*` из папки проектов.

Отчёт — комментарием в задачу или PR на GitHub (`gh issue comment` / `gh pr comment`) и руководителю: по каждой территории — «без изменений» или список листов с отличиями, путь к `summary.png`, вывод «всё
намеренно / есть лишнее». Картинки в контекст целиком не вставлять — только пути и короткий вывод.
