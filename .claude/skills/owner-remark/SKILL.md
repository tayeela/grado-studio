# Замечание владельца → задача на GitHub → правило → исправление → проверка

1. Задача на GitHub: `gh issue create --label "замечание владельца,альбом" --title "<коротко>" --body "<слова владельца дословно, дата>"`.
2. Найти, нет ли уже правила: `docs/wiki/album-rules.md`, `docs/standards/albums/label-rules.md`. Было и нарушено —
   ошибка программы; нет или противоречит — новое правило (поздняя дата главнее).
3. Правило: строка в нужный раздел `album-rules.md` (источник «владелец ДД.ММ, #<issue>») и пункт в `label-rules.md`;
   отменённое — в «Снятые и изменённые правила». **Прежнюю строку на ту же тему правят на месте** (`grep` по цвету, названию элемента, номеру листа в обоих файлах):
   две строки с разным ответом недопустимы — так в своде однажды остались две строки про цвет расчётных СЗЗ (аудит 07.10, #53; действует чёрный точка-пунктир).
   Замечание про **конкретный текст** («пиши вл. 8», «выноска такая») — ещё и строка в `tools/album_expect/` (`all.json` или `<территория>.json`, с причиной): это постоянный тест на слово владельца.
4. Ветка `task/<issue>-<slug>` от `team/t60`; причина в коде (по `docs/wiki/files.md`), исправить источник, а не
   следствие; чистую функцию — с тестом. Ход — комментариями в задачу (`gh issue comment <n>`).
5. Проверка навыком `album-verify` на копии проекта; отличия — только по замечанию; в конце отчёта `report.md` — результат `album_lint.py` (ошибок ноль); отчёт и вырезки — в PR.
6. `tools/gate.sh` зелёный; коммит `grado2 vX.Y.Z: …` + строка в `docs/grado2-changelog.md`; PR в `team/t60` с
   `Closes #<issue>`, после проверки — слить; задача получает метку «готово к выкладке» в PR выкладки.
7. Владельцу — простыми словами: что было, почему, что стало; вырезка «до / после»; ссылка на задачу; что не
   получилось — честно. На сайт — только по слову «выкладывай» (навык `land`).
