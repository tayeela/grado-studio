# Настройки ИИ-агента (.claude)

Здесь настройки Claude Code для ГРАДО 2: роли команды, навыки, хуки (скрипты, которые Claude Code запускает сам) и разрешения.
CLAUDE.md просит запускать сессии из `~/grado-studio`: роли, навыки и хуки загружаются оттуда.
Правила проекта — в [CLAUDE.md](../CLAUDE.md), порядок работы команды — в [docs/team/CYCLE.md](../docs/team/CYCLE.md), карта документов — в [docs/wiki/INDEX.md](../docs/wiki/INDEX.md).

## Роли (`.claude/agents/grado-*.md`)

Восемь ролей команды. Цикл работы команды ([docs/team/CYCLE.md](../docs/team/CYCLE.md)) называет роли агентами `.claude/agents/grado-*.md`.

| Файл | Роль | Назначение | Правка кода |
|---|---|---|---|
| `grado-architect.md` | архитектор и ревьюер | проверяет каждый diff командной ветки до приёмки; следит за форматами данных и границами модулей | нет |
| `grado-backend.md` | бэкенд | `apps/grado2/server.py` и `core/*`: API, формат проекта, ТЭП, печать, PDF и DXF | да, в командной копии, не в main |
| `grado-creative.md` | креативный директор | вид и тексты на экране, UX-сценарии в `docs/ux/grado2-ux.md`; пишет UI-спецификацию до работы и оценивает скриншоты | нет |
| `grado-frontend.md` | фронтенд | `apps/grado2/web`: карта, окна, панель инструментов, слои, стили, редактор листов | да, в командной копии, не в main |
| `grado-gis.md` | специалист по ГИС | источники данных, системы координат МСК и ОГД, форматы импорта и экспорта | да, в командной копии |
| `grado-norms.md` | нормоконтроль | проверяет формулы ТЭП, ограничения и обозначения по нормам, со ссылкой на пункт нормы | нет |
| `grado-product.md` | продукт | голос градостроителя: ведёт бэклог по цели из `docs/product/plan.md`, пишет критерии приёмки | нет |
| `grado-qa.md` | тестировщик | без его PASS задача не принимается: тесты, сценарии в браузере, скриншоты | только файлы тестов |

## Навыки (`.claude/skills/*/SKILL.md`)

| Навык | Когда использовать | Примечание |
|---|---|---|
| `album-verify` | после любой правки печати, подписей, легенды, слоёв или данных альбома и перед словом «готово» | проверка «до / после» на тестовой копии проекта; в frontmatter `context: fork` |
| `owner-remark` | владелец пишет, что на листе что-то не так или как должно быть | замечание → задача на GitHub → правило → исправление → проверка |
| `land` | только по явному слову владельца «выкладывай» | PR команды в `main`, тесты, слияние, деплой, отчёт; в frontmatter `disable-model-invocation: true` |

## Хуки (`.claude/hooks/`)

Проводка хуков — в `.claude/settings.json`, раздел `hooks`.

| Файл | Событие | Что делает | Останавливает ход |
|---|---|---|---|
| `session-start.sh` | SessionStart | только в облачных сессиях (`CLAUDE_CODE_REMOTE=true`): создаёт `~/.grado2/venv`, если его нет, ставит `apps/grado2/requirements.txt`, записывает `CHROME`, если найден браузер в `/opt/pw-browsers`; задаёт `core.hooksPath` = `tools/git-hooks` | нет |
| `grado2_remark_hint.py` | UserPromptSubmit | если сообщение похоже на замечание по альбому (слова про листы, легенду, подписи, цвета, линии и просьба поправить), добавляет подсказку: сначала `docs/wiki/album-rules.md`, затем навыки `owner-remark` и `album-verify` | нет |
| `grado2_check.py` | PostToolUse (Edit, Write, MultiEdit) | для `.js` и `.py` в `apps/grado2` проверяет разбор (`node --check`, `py_compile`); ошибка уходит Claude | нет |
| `grado2_test_gate.py` | Stop, первый | если в копии есть незакоммиченные правки в `apps/grado2` или `core`, запускает `tools/gate.sh` без E2E; провал не даёт закрыть ход | да, при провале |
| `grado2_ux_gate.py` | Stop, второй | если `apps/grado2` изменился с последнего UX-аудита, блокирует остановку и просит пройти сценарии из `docs/ux/grado2-ux.md` и сказать владельцу 2–3 строки; остановки в течение 3 часов после этого проходят | да, один раз |

## Настройки (`.claude/settings.json`)

- `permissions.deny` — запрещает Read, Edit и Write для папки `~/Documents/ГРАДО 2` на Mac владельца и Bash-команды, в которых есть эта папка или порт 8650 (сервер владельца). CLAUDE.md: там не тестировать.
- `claudeMdExcludes` — исключает из загрузки CLAUDE.md по пути `/Users/tayeela/CLAUDE.md`.
- `hooks` — проводка пяти хуков из таблицы выше. Таймауты: `session-start.sh` 300 с, `grado2_test_gate.py` 900 с.
- `extraKnownMarketplaces` + `enabledPlugins` — плагин TokenEconomizer (`microsoft/TokenEconomizer`, Apache-2.0, владелец 30.10.2026): экономит токены — запоминает факты о репозитории из прошлых сессий, убирает неиспользуемые инструменты, ловит зацикливание хода. Claude Code при первом запуске в `~/grado-studio` предлагает поставить плагин; память плагина — `~/.tokeneconomizer` на машине. В облачных сессиях контейнер одноразовый, память не копится. Проверка: `/tokeneconomizer:status`; вернуть убранный инструмент: `/tokeneconomizer:untool`.

## Локальные файлы (не в git)

| Путь | Что это |
|---|---|
| `.claude/launch.json` | настройки запуска предпросмотра, в `.gitignore`. По CLAUDE.md `grado2-test` указывает на основную копию; в рабочей копии команды файл правят локально, помечают `skip-worktree` и не коммитят |
| `.claude/worktrees/` | рабочие копии команды, например `team2` (ветка `team/t60`); создаются командой `git worktree add` (см. docs/team/CYCLE.md). Записаны в `.gitignore` |
| `.claude/.grado2_ux_audited` | метка UX-аудита, пишет `grado2_ux_gate.py`; в `.gitignore` |
| `~/.grado2/test_gate_passed` | отметки прошедших проверок, пишет `grado2_test_gate.py`; вне репозитория |

По docs/team/CYCLE.md локальные папки (worktrees, `/tmp`, `~/.grado2`) — рабочие копии и кэши: ничего не живёт только в них.
