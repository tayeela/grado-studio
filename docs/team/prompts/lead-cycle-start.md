# Руководитель: начало цикла (для себя)
1. В ветке команды: `git merge main` (конфликты — руками, версия и журнал — команды сверху), `tools/gate.sh`.
2. Прочитать `docs/wiki/team.md` (не PROGRESS целиком), открытые задачи GitHub с метками `замечание владельца`, `ждёт владельца`,
   `в работе` (`gh issue list`).
3. Записать решение владельца в правила (`label-rules.md`) раньше кода.
4. Задачи — по шаблону implement.md (разделы переносятся из задачи GitHub «Задача»); не больше трёх агентов сразу, кроме механической работы (аудиты, заголовки файлов,
   перенос файлов — можно много агентов Haiku 5.5, владелец 07.10.2026); у двух агентов не бывает общих файлов.
5. Приёмка: review.md + `E2E=1 tools/gate.sh` + живая проверка (qa-real-check.md или сам) → коммит `grado2 vX.Y.Z` в
   ветке, метка `готово к выкладке` у задачи, запись цикла в PROGRESS.md. Вики обновится сама (CI, `.github/workflows/wiki.yml`).
6. Сессия может оборваться: коммит после каждой принятой задачи, ход работы — комментариями к задаче GitHub; в /tmp/grado-team/<дата>/ —
   только временные файлы.
