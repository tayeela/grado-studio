# План: пересборка интерфейса и сервер на Rust (09.11.2026)

Запрос владельца 09.11.2026: «предложи план полной пересборки фронтэнда для более эффективной работы и архитектуру
бэкэнда на раст». Это предложение, код по нему не менялся. Владелец сам ничего не выбирает: везде ниже стоит решение
по умолчанию. План продолжает [plan-2026-11-08.md](plan-2026-11-08.md) (шаги 1–4 сделаны, v0.99.137–142) и заменяет
в нём шаги 5 и 6 подробным порядком.

Как прочитан запрос: «эффективная работа» — это и работа градостроителя (меньше окон и щелчков от территории до
готовых листов), и работа самой программы (быстрее открывается, не теряет данные, экран совпадает с бумагой).

## Коротко

1. Интерфейс собираем заново в отдельной папке рядом с нынешним, на тех же проверенных библиотеках (Vue 3, dockview,
   Web Awesome, OpenLayers, Konva). Меняется не набор библиотек, а устройство: один поток работы вместо 35 равноправных
   окон, одна модель проекта, одна отмена, одна командная строка на всю программу.
2. Вся предметная логика (проект, координаты, геометрия, ТЭП, знаки, рамки видов, сборка листов) уходит в ядро на Rust.
   Одно и то же ядро работает в браузере (WebAssembly) и на сервере. В интерфейсе остаются только экраны.
3. Сервер становится одной программой на Rust (axum): один файл для сайта, Mac и Windows. Python остаётся эталоном для
   сверки и временным помощником для PPTX и DXF, пока для них нет равной замены.
4. Старая страница `/old` удаляется, когда альбом ППТ КРТ переедет в общие листы.

## Часть 1. Интерфейс заново

### Что остаётся и что меняется

Остаются (решения 08.10 и 08.11, [engine-map.md](engine-map.md)): Vue 3, dockview, Web Awesome, OpenLayers, Konva,
Tabulator, Rete, сборка Vite; команды в духе AutoCAD; схема координат МСК/ОГД; правила альбома. Редактор листов,
рамки видов, автосборка листов и слои знака написаны недавно и переносятся как есть, после чистки.

Меняется устройство:

| Было | Станет | Зачем |
|---|---|---|
| 35 равноправных окон | пять рабочих мест по ходу работы, окна внутри них по-прежнему стыкуются | не искать, что делать дальше |
| JavaScript | TypeScript, типы проекта и ответов сервера строятся из Rust автоматически | ошибка формата видна до запуска |
| общий объект состояния | Pinia (штатное хранилище Vue), проект — один документ | одно место правды |
| отмена в каждом окне своя | одна шина команд: любое действие — команда с именем, отменой и записью в журнал | Ctrl+Z везде одинаков, любое действие набирается в командной строке и повторяется |
| логика в JavaScript | ядро Rust в WebAssembly: проверка проекта, координаты, геометрия, ТЭП, рамки, знаки | экран и сервер считают одним кодом |
| слой целиком в памяти страницы | тяжёлые слои показываются плитками с нашего сервера, в проект идёт вырезка по территории | быстрая карта на больших слоях |
| один файл 3,2 МБ | части подгружаются по надобности (редактор листов, схема расчёта, таблица) | быстрый первый экран |
| своя проверка в браузере | Vitest для модулей, Playwright для сценариев приёмки C–N | одинаково на Mac, Windows и в облаке |

### Пять рабочих мест

Это не шаблоны листов (их нет и не будет), а раскладки окон программы, как рабочие пространства в QGIS и AutoCAD.
Сверху всегда строка шагов с отметкой готовности, внизу командная строка, координаты и масштаб.

1. **Территория.** Карта, поиск по адресу и кадастровому номеру, выбор слоя-границы. Отдельного инструмента «Граница»
   нет: граница — роль слоя.
2. **Данные и оформление.** Каталог слоёв с нашего сервера (ночная копия ГИС ОГД и ЕГКО), слои проекта, окно
   «Свойства» со знаком из слоёв и классами по атрибутам, библиотека знаков, таблица атрибутов.
3. **Проект.** Черчение командами, привязки, ограничения, ТЭП, варианты, схема расчёта.
4. **Виды и листы.** Рамки видов на карте и рядом лист: вид меняется — лист обновляется. Набор видов пользователь
   собирает сам и переносит в другой проект.
5. **Выдача.** Список листов с готовностью (пустая карта, не догрузился слой, не поместились подписи), PDF, PPTX, DXF.

Основа экрана — макет «ГРАДО 3» от 08.11.2026 (доска с лентой, командной строкой, привязками, координатами и
масштабом), проверенный на опыте Безобразово и Мытищинской.

### Порядок работ по интерфейсу

Новый интерфейс живёт в своей папке (по умолчанию apps/grado3/ui) и открывается по своему адресу рядом с нынешним.
Адрес сайта переключается только после прохождения сценариев приёмки.

| Шаг | Что делается | Готово, когда |
|---|---|---|
| И1. Каркас | проект на TypeScript, Pinia, шина команд и общая отмена, командная строка, строка шагов, пять раскладок, подгрузка частей; замер нынешней скорости (первый экран, открытие проекта, число щелчков до PDF) как точка отсчёта | пустой каркас открывает проект и показывает карту; замеры записаны |
| И2. Территория и карта | карта, поиск, роль границы, слои и группы, рисование слоёв через ядро Rust | сценарий «выбрать территорию» проходит в новом интерфейсе |
| И3. Данные и оформление | каталог с сервера, автостиль при загрузке, «Свойства», библиотека знаков, таблица | слой ЗОУИТ из каталога приходит оформленным, стиль из QGIS открывается |
| И4. Виды и листы | перенос редактора листов, рамок видов и автосборки; легенда, штамп, подписи | территория одним щелчком даёт листы набора, PDF совпадает с экраном |
| И5. Проект | черчение, привязки, ограничения, ТЭП, варианты, схема расчёта | сценарии приёмки по эскизу и ТЭП проходят |
| И6. Сайт и замена | каталог проектов, совместная работа, вход; переключение адреса; удаление `/old` и прежнего интерфейса | все сценарии C–N зелёные в новом интерфейсе, старого кода в репозитории нет |

Перед И6 должен быть сделан шаг 5 плана от 08.11: альбом ППТ КРТ в общих листах, с пересборкой Гольяново и
Безобразово на Mac и постраничной сверкой. Без этого `/old` удалить нельзя.

## Часть 2. Сервер на Rust

### Схема

```
        Браузер (сайт)                 Окно программы на Mac и Windows (Tauri 2)
              │                                      │
              └────────── интерфейс Vue ─────────────┘
                     │                    │
          ядро в WebAssembly        запросы /api (JSON, плитки, ход работ)
          (то же ядро Rust)               │
                                          ▼
   ┌──────────────────────── grado: одна программа на Rust ────────────────────────┐
   │ server   адреса /api, раздача страницы, вход и права, задания с ходом работы   │
   │ hub      пользователи, Telegram, роли, ревизии проекта, комментарии (SQLite)   │
   │ ─────────────────────────────────────────────────────────────────────────────  │
   │ layout   листы, рамки видов, атлас, легенда, подписи без наложений, штамп      │
   │ render   операции рисования → пластина PNG, PDF (krilla), SVG                  │
   │ export   GeoJSON, SHP, XLSX, DXF, PPTX                                         │
   │ ─────────────────────────────────────────────────────────────────────────────  │
   │ store    хранилище слоёв на диске с пространственным индексом, вырезка, плитки │
   │ connectors  ГИС ОГД, ЕГКО, НСПД, OSM, Яндекс, ФГИС ТП; шлюз порталов           │
   │ ─────────────────────────────────────────────────────────────────────────────  │
   │ ядро:  model (проект)  crs (МСК, ОГД)  geom  compute (ТЭП)  symbol  plate      │
   └────────────────────────────────────────────────────────────────────────────────┘
        │ ночью: grado warm                         │ пока нет замены
        ▼                                           ▼
   порталы ГИС ОГД и ЕГКО                  помощник на Python: PPTX, DXF
```

### Крейты

Уже есть: `compute`, `geom`, `plate`, `symbol`, `py` (мост в Python, нужен до конца перехода).

| Новый крейт | Что делает | Готовая библиотека | Что заменяет |
|---|---|---|---|
| model | формат проекта, проверка, перевод старых файлов, разделы с ревизиями | serde | `core/model`, проверки pydantic, `migrate.js` |
| crs | МСК, система ГИС ОГД, WGS84 — железное правило 3, сверка с Python бит-в-бит | свой код (правило владельца) | `crs.py`, `msk.js` |
| connectors | порталы; шлюз: один портал из одного места, паузы, не больше 3 повторов; корневой сертификат Минцифры для НСПД | reqwest, tokio, rustls | `core/connectors`, `portalgate.py` |
| store | слои на диске с индексом, вырезка по рамке, плитки для карты, журнал свежести | FlatGeobuf (проверить в начале шага), rstar | кэш `~/.grado2/cache`, `ogd_all.py` |
| layout | листы, виды, атлас, легенда, расстановка подписей, проверка готовности | — | `layout_io.py`, `core/layout`, `viewframes.js`, `autosheets.js` |
| render | PDF с текстом и шрифтами, SVG | krilla (движок PDF Typst), tiny-skia | `core/render`, `print_io.py`, `fonts.py` |
| export | GeoJSON, SHP, XLSX; позже DXF и PPTX | shapefile, rust_xlsxwriter; для DXF и PPTX — проверка кандидатов | `export_io.py`, `dxf_io.py` |
| hub | пользователи, вход через Telegram, роли, команды, ревизии, живые события | rusqlite, jsonwebtoken | `hub.py`, `tglogin.py`, `catalog.py` |
| server | адреса, права, задания с ходом работы, раздача страницы | axum, tower, utoipa (описание адресов) | `server.py` |
| wasm | вход ядра для браузера | wasm-bindgen | логика в `apps/grado2/ui/src` |

Одна программа `grado` с режимами: `serve` (локально), `serve --hub` (сайт), `warm` (ночная выгрузка), `print`
(лист или альбом из файла проекта, для проверок), `check` (сверка с эталоном).

### Правила устройства

- **Слои.** Зависимости идут только сверху вниз по схеме. Ядро не знает о сети и диске, поэтому собирается в WebAssembly.
- **Один формат.** Типы проекта и ответов описаны один раз в Rust; из них строятся типы для интерфейса и описание
  адресов. Новые адреса живут под `/api/v2`, старые работают, пока прежний интерфейс не удалён.
- **Долгие работы — задания.** Выгрузка, сборка листов, печать идут заданием с ходом работы и отменой, а не одним
  долгим запросом.
- **Данные с нашего сервера.** Ночью `grado warm` обновляет все слои ГИС ОГД и ЕГКО старше 20 часов и останавливается
  в 07:00 по Москве, как сейчас. Программа берёт слои из хранилища; портал напрямую — только если слоя там нет.
- **Сайт.** Хранение в SQLite вместо файлов JSON под одним замком; история версий проекта остаётся файлами.
  Вход через Telegram, гости и роли работают как сейчас. Заголовки ответов только ASCII, текст ошибок по-русски в теле.
- **Выкладка.** CI собирает готовую программу под Linux, Mac и Windows и кладёт в выпуск GitHub (как сейчас колёса
  `grado_rs`). Сервер `msk` тем же таймером `grado-pull` берёт программу нужной версии, проверяет `/api/health` и при
  неудаче возвращает прежнюю. Компилятор на сервере не нужен.
- **Программа на компьютере.** Tauri 2: то же ядро и тот же интерфейс в своём окне, без браузера и без установки
  Python. Проекты по-прежнему лежат в «Документы/ГРАДО 2».
- **Сверка.** Python остаётся эталоном. Каждая часть включается переключателем только после зелёной сверки
  (папка `rust/parity`), альбом — после постраничной сверки PDF на копии проекта. Проект владельца не трогаем.

### Порядок работ по серверу

| Шаг | Что делается | Готово, когда |
|---|---|---|
| С1. model и crs | формат проекта и координаты в Rust, сборка в WebAssembly | проекты владельца (копии) читаются и пишутся без потерь; координаты совпадают с Python |
| С2. Геометрия сервера | наложение и площади через Rust вместо приближённого кода (#71) | ТЭП на копиях проектов совпадает или расхождение объяснено |
| С3. store и warm | хранилище слоёв, ночная выгрузка, вырезка и плитки | каталог «Данные» отдаёт слой с сервера быстрее нынешнего, ночной отчёт тот же |
| С4. connectors | порталы на Rust с прежними паузами и повторами | выгрузка по территории даёт те же объекты, что Python |
| С5. layout и render | сборка листа и PDF целиком в Rust, проверки альбома | PDF листов и альбома сходится с эталоном постранично |
| С6. server и hub | axum, SQLite, вход, задания; выкладка готовой программой | сайт работает на Rust, `/api/health` показывает версию, откат проверен |
| С7. Tauri и остаток | окно программы для Mac и Windows; DXF и PPTX на Rust, когда найдена равная замена | установщик без Python; помощник на Python убран или оставлен только для PPTX |

## Общий порядок

Интерфейс и сервер идут двумя дорожками, которые встречаются на ядре:

1. С1 и И1 одновременно (формат проекта и каркас) — основа для всего.
2. С2, С3 и И2, И3 — карта и данные на новом хранилище.
3. Шаг 5 плана от 08.11 (альбом в общих листах, Mac) вместе с С5 и И4.
4. И5, С4.
5. С6, И6 — переключение сайта, удаление старой страницы и прежнего интерфейса.
6. С7 — программа для Mac и Windows без Python.

Каждый шаг — свой PR в `team/t60`, выкладка по готовности, как сейчас. Программа остаётся рабочей на каждом шаге:
новое живёт рядом со старым и включается переключателем.

## Риски

| Риск | Что делаем |
|---|---|
| PPTX и DXF: библиотеки Rust слабее `python-pptx` и `ezdxf` | остаются на Python отдельным помощником; замена только после сверки, возможно никогда |
| Альбом: правила подписей и легенд копились долго | перенос только после пересборки настоящих альбомов и постраничной сверки |
| Два интерфейса живут рядом дольше, чем хочется | новые функции с шага И1 пишутся только в новом; в старом — только исправления |
| Расстановка подписей в Rust даст другой результат | сверка по картинке с допуском, спорные листы показываются владельцу |
| Объём: около 40 тыс. строк интерфейса и сервера | переносим по частям, рабочие модули переезжают, а не пишутся заново |

## Не делаем

Интерфейс на Rust (egui и подобное); предзаданные шаблоны листов; свою библиотеку PDF или PPTX; правку схемы МСК/ОГД;
переписывание всего разом без рабочей программы между шагами.
