# Ядра, движки и библиотеки для ускорения ГРАДО — обзор 08.10.2026

Собрано из трёх веб-обзоров: расчётное ядро на Python, отрисовка в браузере, альбомы и инструменты.
Агенты работали на Sonnet 5.5, а не на Haiku 5.5: смена модели в файле агента в середине сессии
не подействовала. Даты релизов и цифры ускорения взяты со страниц проектов и мной заново не проверялись.
Независимых замеров на данных, похожих на наши, нет ни для одного кандидата. Всё ниже — список кандидатов,
а не доказанное ускорение.

## Исходное положение (проверено по коду)

- `core` — около 15 500 строк на чистом Python 3.14, без внешних пакетов. Наложение, объединение
  и вычитание контуров (`core/geom/grado_geom/overlay.py`), привязки и покрытие написаны вручную.
- Интерфейс `apps/grado2/web` — около 16 000 строк обычного JavaScript без сборки, файлы подключаются
  в `index.html` глобальными скриптами. Внутри OpenLayers, turf.js, litegraph.js, lucide.
- Правило проекта (`CLAUDE.md`): без новых зависимостей в `core` и `apps/grado2`. Всё, что ниже
  помечено «новая зависимость», требует решения владельца.

## Выбрано (по убыванию пользы)

| № | Что | Где ускоряет | Почему подходит | Риски |
|---|---|---|---|---|
| 1 | **shapely 2 (GEOS) + STRtree** | наложение и вычитание зон и участков, покрытие, поиск соседей для привязок | самая зрелая геометрия для Python; замера против нашего `overlay.py` нет (4–100x у авторов shapely — сравнение со старой shapely 1.x, не с чистым Python) | новая зависимость (плюс numpy); нет универсальной сборки для Mac, нужно склеивать две; другое поведение на почти совпадающих границах — нужна сверка ТЭП и альбомов на реальных проектах; дуги придётся разбивать на отрезки |
| 2 | **OpenLayers WebGL-слой** (уже есть в нашей ol 10.10.0, `vendor/LICENSE-ol_10.10.0`) | отрисовка десятков тысяч полигонов на карте | новой зависимости нет; тот же OpenLayers, архитектура не меняется | API помечен нестабильным; штриховки, типы линий и подписи могут отображаться иначе — проверка по листам |
| 3 | **flatbush / rbush** | привязки и выбор объектов в браузере | крошечные, без сборки, rbush для изменяемых объектов | почти нет |
| 4 | **Clipper2-WASM** в Web Worker | булевы операции и отступы в браузере | современный Clipper2, есть глобальная сборка | файл `.wasm` надо отдавать с правильным типом; целые координаты через масштаб; цифр скорости в тексте нет |
| 5 | **TypeScript 7 (tsgo) с checkJs** | не скорость программы, а надёжность кода (вариант Б) | проверяет обычный JS без сборки, в установщик не попадает | программный API ещё нестабилен |
| 6 | **Biome** | проверка и форматирование JS | один бинарник, без сборки | почти нет |

Запасные варианты, только если замер покажет узкое место:
mypyc или Cython для одной-двух горячих функций на Python; skia-python для быстрого растрового
превью листов; pikepdf для сжатия готового PDF-альбома (размер файла, не скорость); orjson
как необязательный ускоритель JSON больших проектов с запасным стандартным `json`.

## Рассмотрено и отклонено

- **Python-геометрия:** GDAL/osgeo (нет готовых пакетов для Python 3.14), GeoPandas, pyogrio, geoarrow,
  pygeoops (таблицы и форматы, ядру не нужны), DuckDB spatial (это база данных), numba (тяжёлая,
  тянет LLVM), rtree (дублирует STRtree), h3 и s2 (сфера, а не плоскость МСК), CGAL и pythonocc
  (3D, тяжёлые), pyclipper (старый Clipper 6), Rust через PyO3 (своя обёртка, вторая цепочка сборки,
  сравнений с GEOS нет).
- **pyproj:** зрелый, но схема координат МСК/ОГД закреплена правилом проекта и не пересматривается.
- **Карта и отрисовка:** MapLibre GL, deck.gl, Leaflet (замена карты без CAD-редактирования),
  Mapbox GL (закрытая лицензия), PixiJS, three.js, regl, luma.gl (свой рендер с нуля), Konva,
  Fabric.js, Paper.js, two.js (редакторы холста, не карты), polygon-clipping и martinez (дублируют
  Clipper2), JSTS (надёжнее turf на сложных операциях, но не быстрее — запасной), OpenCascade.js и web-ifc (3D), Rust/AssemblyScript в WASM (нужна сборка).
- **PDF и PPTX:** PyMuPDF и borb (AGPL), pycairo и CairoSVG (нет пакетов для Mac), Aspose (дорого,
  ограничения на распространение), ReportLab, fpdf2, python-pptx (замена своего рендерера без выгоды),
  Typst (для текстов, не карт), Chromium headless (тяжёлый).
- **Среда и инструменты:** PyPy (застрял на Python 3.11), Mojo (нет Windows), Codon, Nuitka (это
  упаковка, не скорость), JIT и free-threading в CPython 3.14 (без замера пользы нет: JIT около 1,0x,
  один поток free-threading медленнее), uvloop, granian, uvicorn (не нужен асинхронный сервер),
  Vite, esbuild, Bun, Deno (решают задачу сборки, которой у нас нет).
