# Доступ агента к сборке презентаций

Дополнение #167 по указанию владельца: «Приступай к реальным правкам плюс настрой mcp доступ для агентов в градо чтобы они сами могли собирать мне презентации по запросу».

## Выбранный путь

Локальный MCP через stdio на официальном Python SDK maintenance-линии 1.x (mcp>=1.30,<2, MIT).
Он обращается к проверяемым HTTP-командам самого ГРАДО через httpx, без управления браузером,
скриншотов и передачи всей геометрии модели. Новый серверный сборщик содержания нового набора использует
sushpol_io и канонический паспорт; его сцены рендерятся существующими SketchMapFrame, ReportLab/python-pptx.
Это единый путь для UI и MCP, а не отдельный упрощённый экспорт агента. Прежние наборы не меняются.

Слой MCP не получает произвольный shell/SQL/URL/путь. Адрес сервера задаёт конфигурация администратора:
http разрешён только для loopback, удалённое соединение требует https. Доступ — существующий X-Grado-Token
для локального закрытого сервера или сессионная cookie для hub/Telegram. Секреты читаются из отдельного
файла/окружения, не пишутся в project/лог/ответ инструмента. У hub проверяется право read/edit конкретного
projectId на каждой операции, включая статус, отмену, получение файлов и повторное открытие.
MCP не предоставляет обход входа и прав. Сетевые обращения к порталам идут только через существующие коннекторы/Gate.

## Инструменты

- grado_health: версия/возможности сервера, без секретов.
- grado_list_projects: доступный пользователю каталог и краткий состав, без геометрии.
- grado_create_project: название и GeoJSON границы WGS84 либо явные координаты МСК; без исходных слоёв.
- grado_project_status: территория, слои/охват/проблемы, листы и версия подготовки.
- grado_prepare_presentation: projectId, обновить ли источники, включать ли автопанорамы; возвращает runId.
- grado_preparation_status: projectId/runId, ждать обновления до 15 секунд; этапы, причины неполноты, готовность.
- grado_cancel_preparation: отмена только своей доступной задачи, принятые данные сохраняются.
- grado_export_presentation: projectId/runId, pdf/pptx, явно draft; файл скачивается в настроенную папку результатов,
  инструмент возвращает путь, хеш и перечень проблем. Нет ложного «готово» при пропусках.
- grado_replace_photo: projectId/photoId и путь только внутри настроенной папки загрузки; проверка изображения,
  явные координаты/направление либо подтверждение прежних; ID сохраняется.

Полная модель проекта не передаётся в контекст по умолчанию. Конечные значения и карты берутся из источников,
не генерируются моделью. Неподтверждённые права/ОКС, неполное покрытие и ошибки порталов видны в отчёте.

## Общий серверный сценарий

POST /api/preparation/start {projectId,refresh:boolean,photos:boolean,expectedProjectRevision,commandId}
проверяет write, границу/профиль, получает lease и начинает одну ограниченную задачу в текущем процессе.
Никакого отдельного брокера/базы очередей. На проект один run; один тяжёлый этап на процесс. Задача не
продолжается после перезапуска сервера: при открытии сохранённое running становится interrupted.
GET /api/preparation/status?projectId=…&runId=… возвращает этап/отчёт только после проверки прав.
POST /api/preparation/cancel отменяет текущий run. GET /api/preparation/export возвращает проверенный
файл одной версии с теми же правилами доступа. Неполный результат требует draft=true.

План получает источники внутри ГРАДО, сохраняет подтверждения, считает содержание/доступность,
скачивает кадры, собирает все 14 видов и продолжения. Метаданные и единая print-сцена сохраняются
с проектом. Новый UI вызывает тот же start/status и показывает результат существующим SVG-превью/печатью.
Клиент не вычисляет другую версию таблиц/нумерации. Ручные правки/обновления, CAS/журнал и checkpoint
следуют implementation-contract.md. До завершения всех приёмочных проверок набор помечен экспериментальным.

## Проверка

Тесты HTTP: отсутствие входа, viewer, чужой проект/run, некорректные координаты, параллельный запуск,
отмена/перезапуск, пустой и частичный источник, сохранение/повторное открытие, запрет ready-экспорта при пропусках.
Тест настоящего MCP: запуск stdio-процесса официальным ClientSession, initialize, tools/list, tools/call,
создание искусственного проекта и получение PDF/PPTX. Не выдавать это за живую приёмку порталов.
На копиях Безобразово/Гольяново — реальные источники/страницы/замена кадра и album_check.
Codex-конфигурация сохраняется с резервной копией; существующие MCP не удаляются. Текущий чат может
потребовать нового подключения хоста, поэтому отдельно проверяется именно SDK-клиент, а не запись в config.

Источники: https://py.sdk.modelcontextprotocol.io/v1/ и https://learn.chatgpt.com/docs/extend/mcp?surface=cli.

## Уточнения по независимой проверке дополнения

Для нового набора нормативен серверный путь. Единственная функция sushpol_io.build_spec получает
неизменяемый снимок проекта и подтверждения, возвращает PrintSpec + отчёт + обновлённые метаданные.
UI и MCP запускают её через start; UI не формирует второй candidateProject через iframe. Старый
iframe-протокол остаётся только у прежних наборов и ручных действий редактора, не управляет серверным run.
Commit нового набора получает серверный кандидат по runId, клиент не присылает доверенный candidateProject.

Исполнитель нового run — серверный worker; lease renew каждые 10 секунд выполняет он, не вкладка/MCP.
Отключение клиента не отменяет уже принятый ограниченный run. Перед каждым новым получением и под
проектной блокировкой перед checkpoint/commit повторно проверяется edit-доступ сохранённого actor.
Actor берётся только из Ctx/проверенной сессии, а не ownerClientId/тела запроса. Отзыв прав/блокировка
завершает задачу без последующих записей; результат не выдаётся через status/export без текущего доступа.
При остановке процесса lease истекает, записанный run считается interrupted, автоматического возобновления нет.

grado_prepare_presentation обязан принимать commandId (UUID) как ключ повтора. Сервер до ACK start
сохраняет (actor,projectId,commandId)→{runId,argsDigest,state,createdAt}. При одинаковом ключе/аргументах
возвращается тот же runId, в том числе после рестарта; при других аргументах — version_conflict.
Status принимает runId либо commandId для разрешения неизвестного исхода отправки. Исходная ревизия
не включается в argsDigest повтора: уже принятая команда возвращает прежний исход после изменения проекта.
Идентичность проекта/actor и настройки refresh/photos/recipe включаются. Возобновление прерванного run —
новый commandId с resumeRunId; повтор старого start не создаёт вторую задачу. Хранится 64 последних
соответствия на проект в metadata, неизменяемый результат commandId не заменяется новым запуском.
Эти правила имеют приоритет для нового набора над пунктами старого клиентского протокола.

## Предел рамки района

Рамка крупного района ТиНАО может превышать предел встроенного источника. Она не должна увеличивать запрос всех крупных листов до нескольких тысяч км² или молча заменяться областью «территория + 60 м». План сохраняет такую рамку как deferredSources с budget_exceeded, а обязательные данные крупных листов получает для их собственных рамок. Неполный районный лист остаётся неготовым. У серверной подготовки вызов встроенного fetch не передаёт territory для неявного уменьшения уже рассчитанного bbox.

При продолжении refresh=false после записанного failed ЕГКО сначала проверяется запасная векторная основа Яндекса. Если все её роли подтвердили полное покрытие рабочей рамки, повторная загрузка неудавшихся общегородских слоёв ЕГКО не требуется. ПЗЗ использует тот же выбор основы. Это не признание отказавшего источника успешно полученным: исходная неудача остаётся в журнале, а сцена ссылается на реально проверенный запасной источник.
