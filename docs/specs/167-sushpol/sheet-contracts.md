# Содержание и готовность каждого вида листа

Часть [ТЗ #167](../167-sushpol-mytishchi.md). Порядок соответствует 14 физическим слайдам образца.
Композиции — [паспорт вёрстки](layout-contract.md); состояния/ревизии — [общий контракт](implementation-contract.md).

## Общие правила полей

Значение = {value, state, sourceKey, objectKey, sourceField, dataRevision, basis, formulaId}.
state: source, confirmed, calculated, missing, conflict. Для confirmed обязательно основание;
для calculated — formulaId и ссылки на входы. Нулевое значение допустимо только как подтверждённый факт
или результат расчёта; пустая строка не является нулём. «Нет сведений» можно напечатать только после
принятого допустимого исключения, с сохранением кода/области в отчёте; автоматически прочерки не ставятся.
Сборка не выдаёт числовой итог по неполному набору как полный итог территории.

Готовность ready = полные подтверждения нужных источников по области листа + валидные обязательные поля
или разрешённое здесь исключение + отсутствие конфликтов + проверка компоновки + совпадение зависимостей.
Сетевой сбой/неизвестный исход не принимается за подтверждённое отсутствие. Исключение allow_missing
допускается только для явно названных ниже полей, на конкретный объект/поле/ревизию, с основанием владельца.
Подтверждённый empty убирает соответствующие объекты/знаки, сохраняет вид листа и запись в отчёте.
Карта без обязательного покрытия может быть выгружена только черновиком, а не как полный комплект.

Территория — введённый/выбранный владельцем валидный Polygon/MultiPolygon МСК с контекстом проекта.
Область запроса — рамка карты плюс радиус влияющих объектов там, где это указано. Базовые карты:
вектор — действующие ЕГКО/Яндекс по роли, снимок — Яндекс, Esri только для подтверждённых дыр по прежнему правилу.
Источник каждого участка снимка сохраняется. Непроверенная подложка не делает карту ready.

### Привязка ролей источников

План использует существующие SOURCES/роли, а не эвристику первого слоя одинакового типа.
При plan сохраняется отображение role→layerId/sourceKey: admin, ortho, vector_base, parcels,
existing_buildings, landuse, redlines, restrictions, general_plan, pzz, pzz_sub, docs_ppt, docs_pmt,
docs_gpzu, social, roads. Конкретный идентификатор из каталога сохраняется в зависимостях листа.

Версия 1 фиксирует начальные sourceKey по ролям:

| Роль | sourceKey |
|---|---|
| admin | gisogd.admin |
| parcels / зарегистрированные ОКС | nspd.parcels / nspd.buildings |
| картографические здания | egko.buildings, при подтверждённом пробеле osm.buildings |
| landuse / social / roads | osm.landuse / osm.social / osm.roads |
| redlines | gisogd.red_lines |
| restrictions | gisogd.red_lines, gisogd.szz, gisogd.vodookhr, gisogd.zouit, gisogd.airfield, gisogd.okn, nspd.zouit |
| general_plan | gisogd.func_zones и gisogd.func_zones_tinao (каждый с полным ответом/empty) |
| pzz / pzz_sub | gisogd.pzz_zones / gisogd.pzz_sub |
| docs_ppt / docs_pmt / docs_gpzu | gisogd.ppt / gisogd.pmt / gisogd.gpzu |
| vector_base | egko.roads, egko.paths, egko.green, egko.water, egko.place_labels, egko.addresses; вне подтверждённого покрытия ЕГКО — yandex.hd_roads/buildings/green/water/transport |
| ortho | существующий sat_io, Яндекс; Esri только под проверенными дырами |

Это исходный список автоплана, не обязательство одновременно показывать все объекты в легенде.
Каждый составной sourceKey раскрывается в полный набор кодов из SOURCES server.py в план и сохраняет
snapshot этой декларации + SHA256. Никакие подслои не пропускаются как «неважные» без явной причины.
SOURCES и GISOGD_API_LAYERS — действующий единый каталог, его числовые коды не дублируются в другом коде.
Если сохранённый hash декларации не совпал после обновления программы, прежний план не продолжается
молча: пересоздать plan, пометить затронутые листы stale, повторно проверить новые части.
Нормализатор не угадывает неизвестный атрибут по похожему названию: отсутствие точного соответствия
даёт missing_field и действие уточнения внутри ГРАДО.

Нормализованный контракт зон = {objectKey,geometry,classCode,title,document:{number,date,title},
parameters:{density,height,coverage},vriCodes:string[],sourceFields:Record<canonical,string>}.
Для GISOGD document_n/document_d/document_1 задают номер/дату/название документа; document_g — ключ.
ПЗЗ: classCode=«Номер зоны», vriCodes=«ВРИ (коды)», title=«ВРИ»; подзоны: classCode=«Номер подзоны»,
parameters=«Плотность, тыс. м²/га»/«Высота, м»/«Застроенность, %», текст=«Регламент».
Генплан: номер = n, иначе number_fz; индекс = fztip, иначе fz_type; название = naimfunkzony,
иначе «Вид зоны», иначе name; фонд = summfondpersp, иначе interval_fo (не «*»).
Не извлекать число из диапазона interval_fo: диапазон сохраняется текстом. Доля зоны на территории =
площадь пересечения/площадь целой зоны в МСК; если фонд числовой, фонд части = фонд×доля,
если диапазон — умножаются обе границы с пометой диапазона. Единицы фонда — тыс. м².
У ограничений classCode берётся из подтверждённого типа подслоя или LineCode для СПРИТ;
название — нормализованное «Наименование»/«Вид зоны»; реквизиты — «Документ» либо document_*.
При двух непустых противоречащих источниках фиксируется conflict, не произвольный приоритет.
Каждое правило сохраняет исходное имя в sourceFields. Отсутствие соответствия даёт missing_field, а не автоматический выбор.
Печатать неизвестный класс разрешено только как собственный подтверждённый класс владельца с новым знаком,
без притворного отнесения к соседнему классу. Это также проверяется в легенде.

## Земельно-правовые поля и карточки

Существующие LABELS server.py нормализуют НСПД; новые поля ниже не объявляются доступными,
если их нет в ответе. Ручное дополнение выполняется внутри ГРАДО с основанием, без обязательной подготовки файла.

| Каноническое поле | Источник/точное поле или формула | Обязательность/исключение |
|---|---|---|
| parcel.key | nspd.parcels «Кадастровый номер»; если нет — _key источника | Надёжный ключ обязателен, без него не объединять объекты и не подтверждать строку |
| parcel.number | Preparation.numbering[parcel.key] | Обязателен; первоначально кадастровые номера сортируются по числовым компонентам, затем _key; новые номера после максимального, удалённые не занимают повторно |
| parcel.address | «Адрес» | allow_missing при подтверждённом отсутствии; не брать адрес соседнего участка |
| parcel.area_m2 | «Площадь уточнённая, м²», иначе «Площадь участка, м²» | Положительное конечное число. Если оба есть и различны, приоритет уточнённой с сохранением обоих источников. Геометрическая площадь — отдельное поле, не замена кадастровой без confirm_value |
| parcel.cadNumber | «Кадастровый номер» | allow_missing только при другом надёжном objectKey, печать «не присвоен» лишь при подтверждённом статусе, иначе «нет сведений» по принятому исключению |
| parcel.rightType | «Вид права» | Обязательно либо allow_missing. «Форма собственности» — отдельное поле, не замена вида права |
| parcel.ownership | «Форма собственности» | Для заливки собственности; отсутствующее не объявлять государственной/частной, показывать собственный знак «нет сведений» только по принятому исключению |
| parcel.holder | Отдельные реквизиты правообладателя документа либо Override с основанием | Самостоятельного подтверждённого поля в исторической копии нет. Обязательно либо allow_missing |
| parcel.rightDocument | Номер/дата/тип правоустанавливающего документа из структурированного ответа/уточнения | Не document_n градостроительного документа. Для каждого компонента allow_missing; not_applicable только если подтверждённый вид права не имеет договора |
| parcel.validity | Начало/конец/бессрочность из того же документа | Не дата загрузки. Для отсутствия — allow_missing; «бессрочно» только подтверждённое значение |
| parcel.purpose | «ВРИ», отдельно фактическое использование | Цель использования таблицы — ВРИ документа. При отсутствии allow_missing; фактическое использование не выдаётся за ВРИ |
| parcel.notes | Подтверждённое примечание источника/владельца | Необязательное, пустая ячейка без исключения; в других колонках пустота требует правил выше |
| oks.key, geometry | nspd.buildings: «Кадастровый номер»/_key и геометрия | Обязательны для подтверждённого перечня; полигон OSM остаётся картографической застройкой, не зарегистрированным ОКС |
| oks.parcelKey | Структурированная ссылка исходного кадастрового документа на ЗУ либо confirm_relation с основанием | Геометрическое пересечение — только candidate. Если подтверждённая связь с несколькими ЗУ, связь many-to-many, но итог по территории считает oks.key один раз |
| oks.area_m2 | nspd.buildings «Площадь, м²» | Это зарегистрированная площадь объекта, не СПП. Нет площади — allow_missing конкретного ОКС, сумма карточки обозначается неполной в отчёте |
| card.oksCount | Число уникальных подтверждённых oks.key, связанных с ЗУ | Ноль только при подтверждённом полном перечне/уточнении отсутствия, не при пустом слое здания после ошибки |
| card.oksArea_m2 | Сумма известных oks.area_m2 подтверждённых связей | При неполноте не печатать частичную сумму как полную; нужны дополнение/исключения и текст «нет полных сведений» |

Для таблицы используются колонки образца в том же порядке: №, адрес, площадь, кадастровый номер,
вид права, землепользователь, документ, период, цель, примечания. Карточка использует ту же запись,
не вычисляет права и номера заново. Несколько контуров одного кадастрового номера — одна запись с полной
MultiPolygon; разные _key без кадастрового номера остаются разными. Пересечение с территорией ненулевой
площади включает ЗУ в список; одно касание линии не включает, фиксируется только в геометрическом отчёте.

## Показатели существующего положения

В таблице сохранены строки физического слайда 5, а не показатели будущей застройки.
Снос — отдельная колонка, только при подтверждённом перечне demolishKeys владельца/документа.
Отсутствие перечня не означает, что все здания сносятся или сохраняются. Для колонки допустим
not_applicable владельца с основанием; числовые нули без данных не ставятся.

| Строка/единица | Расчёт/источник | Проверка и отсутствие |
|---|---|---|
| Площадь территории, га | площадь валидной территории в МСК /10000 | Обязательна без исключения; 100×100 м = 1,000 га; не сумма площадей целых ЗУ |
| Соотношение жилой/нежилой застройки, % | суммы подтверждённой СПП жилой и нежилой групп / общая СПП ×100 | Классы и СПП всех учитываемых объектов обязательны либо allow_missing показателя целиком. При нулевом знаменателе «не применимо» только после подтверждённого отсутствия застройки |
| СПП всего, в т.ч. нежилых зданий, тыс. м² | сумма подтверждённой суммарной поэтажной площади /1000; нежилая сумма отдельно | Не nspd «Площадь, м²» и не площадь контура×этажность по умолчанию. Если нет СПП в доступном ответе — уточнение из документа либо allow_missing показателя |
| общественные / производственные-коммунальные / смешанные, тыс. м² | группировка той же подтверждённой СПП по принятому классу использования | Один объект не попадает в две группы; нераспознанный класс требует решения. Сумма групп равна нежилому итогу при полном разбиении |
| Нежилая наземная площадь, тыс. м² | отдельное подтверждённое значение по объектам/документу, сумма /1000 | Не равно СПП автоматически, подземные площади не вычитаются по догадке; allow_missing показателя |
| Рабочие места, мест | сумма подтверждённых существующих рабочих мест по объектам/документу | Не норматив новой застройки/не площадь×коэффициент. Неотрицательное целое либо allow_missing показателя |

Контроль: подтверждённая СПП 4000 м² жилой и 6000 м² нежилой даёт 40/60 % и 10,00 тыс. м² всего.
Если известна площадь одного ОКС, а второго нет, частичная сумма не становится итогом. Исключение
позволяет напечатать «нет полных сведений» в показателе, но не получить неподтверждённую цифру.
Отображаемое округление делается после расчёта: площадь территории 3 десятичных га, СПП 2 десятичных тыс.м²,
доли 1 десятичная, ЗУ/ОКС 2 десятичных м². Вычисления и связи используют исходную точность.

## Образование: однозначный resolver

Новый набор использует ключи существующего SERVICES:
«детские сады · Москва (2151-ПП)» и «школы · Москва (2151-ПП)» для московской территории;
федеральные «детские сады · 300 м»/«школы · 500 м» автоматически не выбираются.
Это повторное использование принятых в программе параметров; не утверждение актуальности нормативного акта.
Проверка действительности норм перед нормативным заключением — отдельная содержательная задача.

Округ определяется пересечением территории с gisogd.admin, «Уровень»=округ, «Наименование».
При нескольких округах территория делится по их границам; круги для каждой части строятся по правилу
этой части и обрезаются её геометрией. Объект может находиться вне части, если круг доходит до неё.
Для ЦАО детсад 500 м; школы — radius=null: показываются объекты/окружная граница, круги школы не рисуются.
В отчёте сохраняются ruleKey, norm из SERVICES и причина radius_not_defined; это штатное правило,
не сбой. Не делать из него заключение о полной обеспеченности. Прочие московские округа: детсад 300 м,
школа 1000 м. Неизвестный/неподтверждённый округ — unknown_rule и needs_decision, не правило «прочие».
Территория вне Москвы в первом выпуске требует явно выбранного правила владельцем и новой версии параметров;
московское правило не применяется автоматически. Коэффициент высокой плотности −30 % в новом наборе выключен.

Геометрия кругов — МСК, 128 отрезков, аналитическая проверка дистанции включает границу.
Получение social охватывает территорию плюс максимальный применимый радиус (1000/500/300 м),
включая объекты снаружи. У пустого полного ответа — zero объектов и пустая зона, у сбоя — needs_data.
Это радиальный метод, NWalk и его граф/скорость не вызываются. У медицины остаётся отдельно принятый
approximate_radius с подписью владельца; правила образования не подменяют её параметры.

Контрольные случаи: ЦАО (500/null), иной подтверждённый округ (300/1000), неизвестный округ (блокировка),
пересечение ЦАО/СВАО (две обрезанные части), центр объекта на границе радиуса (включён),
объект снаружи территории, неполное покрытие social и полный empty.
