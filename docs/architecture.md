# Архитектура «ГРАДО Студии»

## Инварианты

1. Одна модель — три представления: «Карта», «Чертёж», «Альбом» — виды поверх одной доменной модели, экспортов между ними не существует.
2. Local-first: файл проекта самодостаточен, облако — надстройка.
3. Всё производное реактивно: ТЭПы, легенды, таблицы, листы, нормоконтроль — материализованные представления, редактируются только через источник.
4. Внутренняя СК проекта — МСК, метры, double; трансформация внешних данных один раз на входе.
5. Кривые (дуги, клотоиды) хранятся параметрически; линеаризация только на границах (GEOS, экспорт).
6. Ядро без UI: headless CLI/Python для тестов, пакетных выгрузок, серверного рендера.

## Процессы

| Процесс | Роль | Причина изоляции |
|---|---|---|
| Приложение | UI, ядро, рендер, вычисления | — |
| Сервис данных | Коннекторы НСПД/ФГИС ТП/ГИСОГД, кэш, индексатор | Фоновая работа, независимые падения |
| DWG-мост | ODA SDK | Изоляция краха и лицензии |
| Python | Плагины (встроенный CPython) | API только через SDK |

## Слои

Рабочие пространства (Qt) → Реактивное ядро (команды/undo, граф зависимостей, ТЭП и нормоконтроль) → Доменная модель (объекты+классификатор, стили, документы, версии) → Ядра C++ (геометрия/топология, СК, рендер+текст) → Хранилище (GeoPackage `.grado` / PostGIS-хаб).

## Ключевые решения

- **Файл проекта** — GeoPackage с доп. таблицами: классификатор (на базе 433/пр), стили, листы, определения ТЭП, правила, журнал дельт. Геометрия по SQL/MM (CompoundCurve, CurvePolygon). Провенанс обязателен: источник, дата, реквизиты документа.
- **Реактивное ядро** — один путь изменений: инструмент → команда → дельта → журнал → граф зависимостей → фоновый пересчёт → инвалидация видов. Журнал дельт закрывает undo, автосейв, синхронизацию и ветки вариантов.
- **Топология** — persistent coverage для функциональных зон и межевания: общие границы хранятся один раз.
- **СК** — PROJ (ГСК-2011, зоны МСК) + модуль калибровки закрытых ключей МСК по опорным точкам.
- **Рендер** — одна стилевая машина, два бэкенда: GPU (экран) и векторный PDF/X (печать). WYSIWYG за счёт общего стилевого байткода. Текст: HarfBuzz/FreeType, русские переносы.
- **Альбом** — документ → мастер-страницы → листы → фреймы (карто-вьюпорт, таблица, текст, легенда, штамп); все фреймы — узлы графа зависимостей.
- **Вычисления** — метрики и правила описываются данными (см. `core/compute`): выражение + граф зависимостей; региональные РНГП подключаются пакетами пресетов.
- **Сервис данных** — контракт коннектора: discover / fetch / diff / subscribe; неизменяемые датированные снимки (фиксация ИРД); общение по локальному gRPC/IPC.
- **Экспорт** — DWG/DXF (кривые нативно), PDF/X, GeoPackage, XML-схемы ГИСОГД, каталоги координат красных линий.

## Стек

C++20 + Qt 6, встроенный CPython, GDAL/GEOS/PROJ, SQLite/GPKG, PostGIS, ODA SDK, HarfBuzz/FreeType, wgpu/Qt RHI. Потоки: UI, рендер, пул фоновых задач; запись в SQLite через одну очередь (WAL).

## Порядок прототипирования (по риску)

Все четыре рисковые точки закрыты эталонными реализациями:
1. Реактивное ядро с журналом дельт — `core/reactive`.
2. ТЭП-движок — `core/compute`.
3. Топологический coverage — `core/geom`.
4. Стилевая машина с двумя бэкендами — `core/render` (+ альбом `core/layout`).

## Статус

- `core/compute` — прототип готов: декларативные метрики, граф зависимостей, инкрементальный пересчёт, CLI, 17 тестов. Пресет `moscow_krt` (константы методики КРТ восстановлены из genplan.tech, 2026-07-02): СПП→НП 0.9, квартиры 0.65 от СПП жилой части, 33 м² квартир/чел, 2.1 чел/кв., ДОО 44 и школы 90 мест/тыс. чел (зона 1), поликлиники 13.2+5.8 посещ./тыс., пороги размещения 100/150/320, парковка 257 мм/тыс. чел × k_rail (0.75|1) × k_ba (0.2|0.5).
- `apps/calc-web` — калькулятор на том же пресете, URL-параметры совместимы с genplan.tech.
- `core/model` — прототип готов: `.grado` = GeoPackage на чистом sqlite3 (валидирован GDAL/OGR из QGIS-LTR: драйвер GPKG, слои и СК читаются, геометрия valid), классификатор как JSON-пресет (10 базовых классов, поле code_433pr для сопоставления с 433/пр), обязательный провенанс (source/source_date/source_doc, NOT NULL), мост tep_bridge: площади слоёв с tep_role → входы ТЭП-движка. Рабочая СК до модуля калибровки МСК — EPSG:32637 (UTM 37N, метры). 21 тест.
- `core/connectors` — прототип готов: контракт discover/fetch/diff/subscribe; хранилище неизменяемых датированных снимков (sha256, verify ловит правку задним числом, повторное сохранение идемпотентно); диф по стабильному ключу; импорт снимка в проект одной записью журнала (Session.bulk, атомарно, один undo); подписки check() — «на территории изменился документ». Коннекторы по протоколам работающего GRADO-моста: НСПД-захват (перехват fetch с intersects, EPSG:3857, options→opt_*, дедуп по геометрии, ключ — кадастровый номер), ФГИС ТП (discovery json_layers_stp_list.jsp по UIN + WFS 2.0.0, CQL uin/mt_classid/kit/mt_status, типы min_eco_test:geo_db_data_fgistp_pol|lin|pnt; транспорт заменяемый — вне браузерной сессии портал отвечает 403, в продукте транспортом служит WebView сервиса данных), ГИС ОГД Москвы (рекурсивная распаковка ZIP-в-ZIP, SHP МСК-50 → WGS84 через ogr2ogr из QGIS-LTR; параметры МСК-50 с towgs84 — константа OGD_PROJ4). СК без PROJ в эталоне: Web Mercator (точно) и UTM 37N (ряды Снайдера, сверено с PROJ до мм); полный датум-пересчёт МСК-50 — через GDAL. 25 тестов, включая раундтрип SHP МСК-50 через настоящий ogr2ogr.
- `core/geom` — прототип готов: дуги параметрически (from_3pts, линеаризация по сагитте с контролем прогиба, офсет со сменой радиуса по стороне центра), составные пути (сопряжение полилиний тангенциальными дугами — геометрия красных линий, пикетаж point_at_station/stations, офсет G1-цепей поэлементно и ломаных через miter), движок привязок (конец > пересечение > середина > ближайшая, приоритет бьёт дистанцию), топологическое покрытие зон (общее ребро хранится один раз, правка двигает обе зоны, validate: сумма площадей = площадь контура). Ограничения эталона: общие границы совпадают повершинно (нодинг произвольных пересечений — C++ ядро), клотоиды не реализованы. 24 теста.
- `core/render` — прототип готов: стиль = данные к коду классификатора; сцена → единый список операций (clip/path/circle/text в мм листа); два бэкенда без второй реализации стилизации: SVG (экранный прокси GPU) и собственный PDF-писатель (вектор, Flate, кириллица через встраиваемый TrueType: Type0/CIDFontType2/Identity-H, минимальный разбор cmap4/hmtx/head/maxp; корректность xref проверяется тестом побайтово). Подписи: центроид/смещение от маркера, без разрешения коллизий (label engine — C++ ядро). 11 тестов + визуальная сверка страниц через независимый рендер CoreGraphics.
- `core/layout` — прототип готов: документ → листы → фреймы: рамка ГОСТ (поля 20/5), карто-фрейм (та же сцена render — лист не расходится с экраном), легенда из слоёв проекта, таблица (ТЭП живой из движка), текст, упрощённая основная надпись формы 3 ГОСТ Р 21.101 (блок подписей 65 мм + шифр/объект/лист/стадия/организация). Демо-альбом: 2 листа А3 (опорный план М 1:2500 + ТЭП), собирает все модули ядра разом. 5 тестов.
- `core/reactive` — прототип готов: единый путь изменений (команда → обратимая дельта → журнал → подписчики). Журнал в таблицах grado_journal/grado_branches того же файла (local-first), позиции head персистентны — undo переживает перезапуск. Линейная история с отсечением redo-хвоста и защитой от осиротения веток. Ветки вариантов: форк от main, переключение реплеем дельт (main↔ветка и ветка↔ветка через общую базу). TepLink: подписка на слои с tep_role → пересбор входов из геометрии → инкрементальный пересчёт движка; правка нерелевантного слоя пересчёта не вызывает. Упрощения эталона: пересчёт синхронный (в C++ ядре — фоновый пул), создание слоёв не журналируется (только объекты). 21 тест.
