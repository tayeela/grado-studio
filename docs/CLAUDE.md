# docs/ — правила работы с документами

Этот файл Claude Code подгружает, когда агент работает в `docs/`. Карта полок — [INDEX.md](INDEX.md).

## Полки

Живое — на полках, история — в `archive/`. Новый документ кладите **по смыслу**, не в корень `docs/`:

| что пишете | куда |
|---|---|
| как запустить, как пользоваться | `guides/` |
| зачем, цель, план, аналоги, исследование | `product/` |
| ТЗ или контракт функции до кода | `specs/` (файл называется по номеру задачи: `37-sitplan-sheets.md`) |
| сценарий проверки интерфейса, макет окна | `ux/` |
| правило оформления, образец, норма, шрифт | `standards/` (**уходит на сервер**: не складывайте сюда обычные заметки) |
| процесс команды, решение, журнал цикла, шаблон задания | `team/` |
| справка, которую можно собрать из кода | не пишите руками: добавьте страницу в `tools/wiki.py` |
| выполненный план, прежний аудит, документ о закрытой студии | `archive/` |

## Обязательно

1. **Новый `.md` называется в `INDEX.md` или в README своей полки** — иначе `tools/docs_check.py` скажет «ни на какой полке».
2. **Ссылки и пути проверяются**: ссылки Markdown с относительным адресом и пути в обратных кавычках, начинающиеся с `apps/`, `core/`, `docs/`, `tools/` …,
   должны существовать. Журналы и архив не проверяются (они о прошлом). Перенос файла — `git mv`, затем `python3 tools/docs_check.py`: он покажет все битые места.
3. **Страницы `docs/wiki/*.md` с пометкой «генерируется» руками не правят**: `python3 tools/wiki.py` (его же запускают pre-commit и CI).
   Руками пишутся `architecture.md`, `recipes.md`, `files.md`, `conventions.md`, `album-rules.md`.
4. **Журналы только дописываются сверху** (`grado2-changelog.md`, `team/PROGRESS.md`, `team/DECISIONS.md`); задачи и слова владельца живут в
   GitHub Issues, а не в файлах.
5. **Слова владельца** по альбому: сначала правило в [standards/albums/label-rules.md](standards/albums/label-rules.md) и
   [wiki/album-rules.md](wiki/album-rules.md), потом код (навык `owner-remark`).
6. **Документ не копирует код и числа**: ссылается на файл и на страницу вики. Факт, который нужен в двух местах, пишется в одном.
7. Пишите по-русски, простыми словами, без эмодзи; владелец — градостроитель, не программист. Что видно на экране — так и описывайте.

## Заголовок файла кода

Каждый файл кода (`.py`, `.js`, `.mjs`, `.sh`) начинается с комментария «что это» — его печатает `docs/wiki/modules.md`, его же читает агент,
прежде чем открывать файл целиком. Образец:

```python
"""Что делает файл — одной фразой, глаголом.

Кто его вызывает, что читает и пишет, чем проверяется (2–3 строки).
"""
```

```js
/* ГРАДО 2 · что делает файл — одной фразой.
   Кто вызывает, что читает, чем проверяется: tests/<имя>_test.js. */
```

Тесты: первая фраза — что проверяют; строка «Запуск: …». Закрытые программы (`apps/studio`, `apps/wizard`, `apps/calc-web`) не правятся.
