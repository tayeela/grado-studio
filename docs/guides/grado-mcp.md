# Агент собирает презентацию в ГРАДО

MCP `grado` позволяет агенту создать проект по границе территории, получить исходные
слои встроенными средствами ГРАДО, собрать существующее положение по мытищинскому
образцу и скачать PDF/PPTX одной версии. Геометрия слоёв остаётся на сервере.
Это экспериментальная реализация задачи #167; наличие доступа ещё не означает,
что конкретная территория получила полный комплект исходных сведений.

## Запуск отдельно от основной программы

Требуется Python 3.11 или новее. Из корня репозитория:

```sh
python3 -m venv ~/.grado2/agent/venv
~/.grado2/agent/venv/bin/pip install -r apps/grado2/requirements.txt -r tools/requirements-mcp.txt
~/.grado2/agent/venv/bin/python tools/grado_agent_server.py
```

Сервер слушает только loopback, порт 8667. Занятый порт означает отказ запуска.
Рабочий порт владельца 8650 не используется. Проекты, кэш и ключ находятся в
отдельной папке `~/.grado2/agent`; ключ создаётся автоматически с правами 0600.
Параметры `--root` и `--port` меняют эти настройки. Запуск не открывает браузер
и не прогревает порталы. Не публикуйте этот локальный сервер в интернет.

## Подключение Codex

Подставьте абсолютный путь к своему checkout вместо `/absolute/grado-studio`:

```sh
codex mcp add grado \
  --env GRADO_MCP_URL=http://127.0.0.1:8667 \
  --env GRADO_MCP_TOKEN_FILE=/Users/yourname/.grado2/agent/access-token \
  -- /Users/yourname/.grado2/agent/venv/bin/python /absolute/grado-studio/tools/grado_mcp.py
```

Секрет в конфигурацию не копируется: MCP читает файл ключа. У существующих
процессов агента список инструментов может обновиться только в новой сессии.
Для удалённого существующего хаба задаются HTTPS-адрес и `GRADO_MCP_COOKIE_FILE`
с действующей сессионной кукой пользователя. MCP не расширяет его права.
Пользователь с просмотром не может запускать сборку и заменять фотографии.

На Mac владельца отдельный сервер запускает пользовательский LaunchAgent
`tech.grado.agent-dev`; его конфигурация находится в `~/Library/LaunchAgents`.
Это сервер рабочей ветки, а не выпуск основной программы. После правок Python
его нужно перезапустить. Остановка: `launchctl bootout gui/$(id -u)/tech.grado.agent-dev`.
Удаление записи MCP: `codex mcp remove grado`. Проекты при этом сохраняются.

## Сценарий агента

1. `grado_health`, `grado_list_projects`, `grado_project_status` — соединение и исходное состояние.
2. `grado_create_project` — новая территория, если проект ещё не существует.
3. `grado_prepare_presentation` — сохранить UUID команды и начать импорт/сборку.
   Повтор с тем же UUID и параметрами возвращает тот же запуск; смена параметров
   с прежним UUID запрещена. После потери ответа запуск находится по UUID команды.
4. `grado_preparation_status`, `grado_preparation_issues` — этап и конкретные причины неполноты.
5. `grado_resolve_field` — уточнение отдельного поля объекта или обоснованное
   принятие отсутствия/неприменимости. Значения не подставляются без основания.
6. `grado_export_presentation` — PDF и PPTX с одним run_id. При неполноте требуется
   явное `draft=true`; на листах стоит «Черновик». Нельзя представлять его готовым альбомом.

Результаты по умолчанию скачиваются в `~/Downloads/ГРАДО — результаты агента`.
`GRADO_MCP_OUTPUTS` меняет папку. Свои фотографии помещаются в её подпапку
`загрузка` (`GRADO_MCP_UPLOADS`), затем вызывается `grado_replace_photo` со стабильным
photo_id и точкой/направлением либо явным подтверждением прежних. Выход за папку
загрузки запрещён. После замены нужно повторить сборку с `refresh=false`.

## Что проверяется

Тест [test_grado_mcp.py](../../apps/grado2/tests/test_grado_mcp.py) запускает настоящий
stdio SDK-клиент и HTTP-сервер на случайном порту: авторизация, перечень инструментов,
создание, повтор старта, получение статуса, PDF/PPTX. Сетевые источники в этом тесте
намеренно недоступны: проверяется честный неполный результат, а не свежесть данных.

Сборщик использует действующее печатное ядро, сохраняет контрольную версию до
импорта, проверяет права перед записью и не подменяет ручные изменения результатом
длительной операции. Перезапуск сервера прерывает незавершённую подготовку; повтор
команды не запускает её скрытно. Для продолжения нужен новый UUID команды.

Границы ограничений: недоступные порталы, недостаточные атрибуты ЕГРН и недостающие
фотографии остаются причинами неполноты. Автоматическая сборка не выдумывает
правообладателя, реквизиты договора, СПП или рабочие места. Полная визуальная
приёмка на реальных проектах и браузерная проверка обязательны до выпуска.
