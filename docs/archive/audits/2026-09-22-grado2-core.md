# Core audit for ГРАДО 2 (22.09.2026)

The audit checked what can be reused from `core/*` and `apps/studio/studio_core.py` for the new
flow: existing situation from real sources → parametric node graph → generative sketch with ТЭП.
Three parallel reviewers covered it (compute/model/reactive; connectors plus live sources;
geom/render/layout), and the main facts were rechecked by hand.
Tests before the changes: 507 green. After: 513 green.

## Verdicts

| Package | Verdict | Role in ГРАДО 2 |
|---|---|---|
| core/compute | keep, with fixes | ТЭП via `/api/tep`, KRT preset |
| core/connectors | keep | Source of real data: NSPD, OSM, GISOGD (all verified live) |
| core/render: styles JSON + generators | keep | Future source of ЛГР/Genplan styles for OpenLayers |
| core/render: scene + PDF | keep for later | Sheets stage |
| core/layout | not needed now, code kept | Sheets stage |
| core/model | not needed now | Future project save (.grado) |
| core/reactive | drop for ГРАДО 2 | Undo goes to the frontend, variants become snapshots |
| core/geom | keep Arc/Path/stationing | Buffer and boolean ops for the graph run in the browser on Turf.js; shapely is not installed |

## Fixed in this commit

- `Engine.set_inputs` validates every key BEFORE writing. Previously an unknown key left the
  engine half-updated.
- The KRT preset `calc_area = max(terr_area - restrict_area, 0)`: population no longer goes
  negative when restrictions exceed the territory.
- OSM `osm.py`: inner rings of multipolygons (holes) are kept, not dropped.

## Found but NOT fixed (not on the ГРАДО 2 path, left for later)

- compute: `where()` evaluates both branches; division by zero is not wrapped in `ExpressionError`.
  `regulations/moscow_urban_planning.json` is not loaded by any code. The repo `CLAUDE.md`
  claims it is connected; that claim is inaccurate.
- model:
  - Collision of `a.b`/`a_b` in table names.
  - WKB Z/M and big-endian are not handled.
  - DXF does not escape newlines.
  - A commit per feature.
- reactive: checkout to a nonexistent branch corrupts state; `TepLink` and `tep_bridge` treat
  import layers differently.
- geom:
  - Division by zero on repeated vertices and zero-length segments.
  - A 180° turn in `fillet_polyline`.
  - The miter offset has no limit or cleanup.
- render:
  - An empty ring in PDF.
  - `fill_opacity` is ignored in PDF.
  - No ToUnicode, no font subsetting.
- layout: the legend does not draw hatching or markers; no line wrapping in frames.
- connectors:
  - ФГИС ТП is not resolved by the router DNS (`mnp.economy.gov.ru`, works via 77.88.8.8), and
    its layer list takes ~35 s.
  - The NSPD key is the portal id, not the cadastral number.
  - Relief is not clipped to the bbox and needs Pillow.
  - The `_ssl_context` helper is duplicated 5 times.
  - The canvas origin 413000/6178000 is hardcoded in 5 places.
- studio_core: the "fact" and the "norm" in ТЭП are not linked (population comes from the density
  slider). Parameter ranges are hardcoded and out-of-range values are silently dropped. A third
  copy of the preset lives in `pages-core.js`.

## New app: apps/grado2

- `server.py` (stdlib, no dependencies):
  - `POST /api/fetch` uses the core connectors, with parallel sources and area limits. It returns
    GeoJSON WGS84 with provenance, and fields get readable names.
  - `POST /api/tep` uses the core engine. Population and social demand are computed only from
    the new buildings; the total density includes the kept buildings.
- `web/`: OpenLayers + Turf.js + litegraph.js + Lucide, loaded from the jsdelivr CDN.
- Verified live on an area in Khoroshevo-Mnyovniki (45.9 ha):
  - Loading: NSPD 46 parcels and 56 buildings, OSM 342 roads, GISOGD SZZ and water protection
    zones.
  - Graph: buildable area 20.7 ha → 57 buildings → ТЭП from the core engine.
  - 6 variants: population 7.6–12.7 thousand.
