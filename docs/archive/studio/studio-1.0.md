Статус: сверка от 2026-09-22 принята. Код нового холста не начат.
Старый `apps/studio/web/index.html` не переключался.

Принятый объём 1.0 уже этого документа. Полный CAD из первого брифа
(trim, extend, join, нодинг произвольных пересечений, индекс на каждую
будущую команду) и покрытие школ и ДОО в 1.0 не входят. Кнопок под них нет.

ячейки под него нет.

Дефолты пресета 15 га и 9 этажей вечным ограничением не принимаются.
`compute_tep` не публикует их. Нет границы — в показателях «н/д», альбом

`grado_key` → честный ТЭП → схема кривых → snap и аффинные → фикстура → холст.

## 1. Что 1.0 берёт из беты

Одна модель, три вида: Карта, Чертёж, Альбом.
Файл `.grado` — GeoPackage плюс таблицы `grado_*`. Файл открывается в QGIS,
потому что геометрия лежит в обычных feature-таблицах GPKG (SRS 32637, UTM 37N, метры).
ТЭП, легенда и листы считаются из геометрии и пресета. Ручной ввод цифр ТЭП в таблицу запрещён.
Маршрут объекта в слой — по `layer_id`. Поле `kind` остаётся транспортом схемы
атрибутов на холсте, не ключом слоя.
Классификатор и стили ЛГР правятся генератором `tools/gen_moscow_lgr.py`.
Живой эталон знаков — рабочие QML Москвы. Приказ № 65 остаётся только там, где
генератор явно помечен правкой пользователя (коды без маркера в QML).
JSON `core/render/grado_render/styles/moscow_lgr.json` руками не редактировать.
В библиотеке 55 стилей.

Режимы сервера, уже есть в `apps/studio/server.py`:

- локальный: `python3 apps/studio/server.py`, `http://127.0.0.1:8643`;
- `--hub`: аккаунты и проекты на сервере (`webhub.py`);
- `--cloud` или `GRADO_CLOUD=1`: хост `0.0.0.0`, мост `:8081` выключен,
  серверный импорт выключен (`_server_side_import_enabled` ложен).

Мост расширения GRADO слушает `127.0.0.1:8081`, только локальный режим.
Импорт по пути ограничен каталогом `~/Downloads`.

Подложка OSM — прокси и дисковый кэш тайлов в `studio_core.fetch_tile`.
Sentinel-2 cloudless — источник тайлов `s2` (EOX), не векторный слой.
Рельеф как горизонтали — коннектор `TerrainContours` (Terrarium / SRTM).
В 1.0 рельеф и снимок остаются подложками. Их не кладут в редактируемые роли.

Выпуск, который ядро уже умеет собрать: предпроверка `preflight_project`,
PDF листа `make_print`, альбом АГК `make_album`, DXF R12 `make_dxf` /
`project_to_dxf`, файл `make_grado`.
Автосейв с ротацией — `server.py` (`/api/autosave`, резервные копии 1…10).
Журнал дельт — `grado_reactive` (`undo` / `redo`, ветки).
Сессия студии сегодня дополнительно держит стеки undo в JSON проекта;
журнал ядра и стек холста — два механизма. В 1.0 путь правки один: `Session`.

Браузерная сборка GitHub Pages (`packaging/build_pages.py`, `pages-core.js`)
остаётся отдельным профилем: черчение и IndexedDB. PDF, DXF, альбом и серверный
импорт там не обещать.

## 2. Инвентарь `core/*`

Публичная поверхность — символы без префикса `_` на уровне модуля и публичные
методы классов. CLI `main` в `__main__.py` в контракт HTTP не входит.

### 2.2. `core/geom` — 24 теста

`Arc` (`curves.py`): `from_3pts`, `start`, `end`, `length`, `point_at`,
`point_at_length`, `tangent_at`, `linearize(tol)`, `offset`.
Параметры: центр, радиус, `a0`, знаковый `sweep`. Коллинеарные три точки
отклоняются.

`Path` (`path.py`): `polyline`, `fillet_polyline(pts, radius)`, `length`,
`linearize`, `area`, `point_at_station`, `stations`, `is_g1`, `offset`.
Офсет G1-цепи поэлементно. Ломаная — miter. Смесь без G1 отклоняется.
Радиус, который не помещается в вершину, поднимает `PathError`.

`Snapper` (`snap.py`): `add_segment`, `add_polyline`, `snap`.
Виды: `endpoint`, `intersection`, `midpoint`, `nearest`.
Приоритет вида бьёт дистанцию. Допуск по умолчанию 0.5 м.
Кандидаты отрезка берутся из клеток сетки (шаг — десять допусков, не меньше 1 м).
Пересечения считаются парами внутри одной клетки, не всеми парами чертежа.
Дуги, окружности, перпендикуляр, касательная и центр в индекс не входят.
`add_polyline` не замыкает контур сама.
`rotate`, `scale`, `mirror` — `affine.py`. Они меняют точки и не пишут проект.

`Coverage` (`coverage.py`): покрытие зон с общим ребром.
`from_polygons` требует кольца без дыр и общие границы, совпавшие повершинно.
`edit_edge` двигает обе зоны, узлы концов неподвижны.
`validate` сверяет сумму площадей с внешним контуром.
Модуль прямо пишет: нодинг произвольных пересечений эталон не делает.

Это покрытие смежности. Зон обслуживания ДОО и школ в `core/geom` нет.
Ближайшие примитивы для будущего буфера: `Path.offset`, `Arc.offset`,
а на уровне студии — `make_buffer` (точка становится окружностью).

Тесты: `test_curves_path.py` (12), `test_snap_coverage.py` (12).

### 2.4. `core/reactive` — 24 теста

`deltas.py`: `snapshot`, `invert`, `apply`, `affected_layers`.
Операции дельты — вставка, обновление, удаление одного объекта.

`Journal`: ветка `main`, `create_branch`, `checkout` через `Session`,
`append`, `entries`, головы в `grado_meta`.

`Session`: единственный задуманный путь записи.
`insert_feature`, `update_feature`, `delete_feature`, `bulk`, `undo`, `redo`,
`create_branch`, `checkout`, `subscribe`, `log`.
Идентификатор слоя в вызовах сессии исторически называется `code`;
реализация обязана резать по `layer_id`, когда слой не 1:1 с классом.

`TepLink.sync`: если изменился слой с `tep_role`, площади заново кладутся во входы
движка. Удаление всех объектов роли даёт 0, а не прошлое значение.
Это единственный «граф» ядра. Узлов концепции, флага «перебито вручную» и
нарезки корпусов нет.

Тесты: `test_session.py`, `test_branches.py`, `test_tep_link.py`.

## 3. Контракт файла, который 1.0 не имеет права размыть

1. Единственный source of truth после записи — GeoPackage и `grado_*`.
2. СК до отдельной калибровки — EPSG:32637, метры.
3. Каждый импортированный объект несёт `source`, `source_date`, `source_doc`.
4. `layer_id` стабилен и переживает круг `.grado`.
5. `grado_key` коннектора переживает круг `.grado`. Холст по-прежнему зовёт
   поле `srcKey`. `build_project` пишет его в колонку `grado_key`.
   `grado_to_features` возвращает и `grado_key`, и `srcKey`. Журнал дельт
   тащит колонку через undo.
6. Дуга, окружность и сопряжение с радиусом пишутся в колонку `curve`
   схемой `arc` / `circle` / `path` (`curve_spec`). Координаты схемы — в СК
   проекта. Колонка `geom` остаётся WKB-ломаной: её тесселяция (`tessellate_curve`,
   сагитта 0.05 м) нужна QGIS и DXF R12. При открытии параметры берутся из
   `curve`, не из ломаной. Старый JSON в атрибутах `arc` / `circle` ещё пишется
   и читается, если колонки `curve` нет.
7. Нодинг пересечений, trim, extend и join в 1.0 нет. Команд в ленте нет.
8. `Snapper` ищет кандидатов по сетке клеток. Виды те же: конец, пересечение,
   середина, ближайшая точка на отрезке. Дуги в индекс не входят. Аффинные
   `rotate`, `scale`, `mirror` живут в `grado_geom.affine` и не режут топологию.

Расхождение источников рельефа: `TerrainContours.source` равен `terrain`,
`studio_core._PROV_SOURCES` его пропускает, `Project.SOURCES` — нет.
`add_feature` поднимет `ProjectError`. Пока рельеф — подложка, в `.grado` его
не записывать. Если горизонтали станут слоем, сначала добавить код источника
в модель и тест круга.

## 4. Роли слоёв

Роль в 1.0 — то, что видит градостроитель в левой колонке.
Технически это тройка: `layer_id`, код классификатора, `stage`
(`existing` / `project` / `base`). Отдельного поля `role` в GPKG нет.
Заводить второе поле параллельно классификатору нельзя: площадь ТЭП уже
суммируется по `tep_role` класса.

Классификатор сейчас (`classifier_base.json`):

| Код | Заголовок | Геометрия | `tep_role` | Стадия класса |
|---|---|---|---|---|
| `terr.boundary` | Граница проектирования | Polygon | `terr_area` | base |
| `terr.restrict` | Территории, не подлежащие застройке | Polygon | `restrict_area` | existing |
| `cad.parcel` | Земельный участок (ЕГРН) | MultiPolygon | — | existing |
| `cad.zouit` | ЗОУИТ | MultiPolygon | — | existing |
| `tp.func_zone` | Функциональная зона | MultiPolygon, topology coverage | — | existing |
| `pp.red_line` | Красная линия | LineString | — | project |
| `pp.placement_zone` | Зона планируемого размещения ОКС | MultiPolygon | — | project |
| `oks.building` | Здание | Polygon | `building_footprint` | project |
| `uds.road_axis` | Ось УДС | LineString | — | existing |
| `social.object` | Соцобъект | Point | — | project |
| `generic.polygon` / `generic.line` / `generic.point` | Прочее | свой тип | — | project |

Реестр холста `LAYER_TEMPLATES` уже раскладывает источники по `layer_id`.
Один класс может иметь несколько слоёв: проектная зона `project.tp.func_zone`
и `source.fgistp.func_zones` делят `tp.func_zone` и не смешиваются.

Как бриф «анализа существующего положения» садится на этот реестр:

| Что видит пользователь | `layer_id` сегодня | Класс | Дыра |
|---|---|---|---|
| Граница территории | `project.territory.boundary` | `terr.boundary` | задаётся в мастере и видна всегда |
| Участок ЕГРН | `source.nspd.parcels` | `cad.parcel` | |
| Существующие здания | `source.nspd.buildings`, `source.osm.buildings` | `oks.building`, stage existing | тот же `tep_role`, что у проектных зданий; факт СПП считает любой `kind=building` внутри границы. Проектные и существующие надо развести до формулы факта |
| Проектные здания | `project.apo.buildings` | `oks.building`, stage project | пустая или негодная этажность в факт СПП не входит (`floors_unknown`) |
| Дороги | `source.osm.roads` | `generic.line` | класса «существующая дорога» нет; `uds.road_axis` — проектная семантика на стадии existing |
| Вода | `source.osm.water` | `generic.polygon` | отдельного класса реки нет |
| ЗОУИТ НСПД | `source.nspd.zouit` | `terr.restrict` | класс `cad.zouit` в реестре холста не используется |
| ЗОУИТ ОГД | `source.gisogd.restrict` и слои `source.gisogd.zouit.*` | `terr.restrict` | имя из LineCode / названия слоя; безымянный объект подписывается «ЗОУИТ без имени / УИН» |
| Красные линии | `source.gisogd.red_lines`, `project.apo.red_lines` | `pp.red_line` | |
| Соцобъекты | `project.social.objects` | `social.object` | импорт существующих школ и ДОО отдельным слоем не заведён |
| Сети | — | — | коннектора и класса нет. Слой не показывать пустой галочкой |
| Сервитуты | — | — | класса нет. Не рисовать роль заранее |
| Функциональные зоны | `project.tp.func_zone`, `source.fgistp.func_zones`, `source.gisogd.func_zones` | `tp.func_zone` | |
| Пятно ОКС | `project.apo.public_zones` | `pp.placement_zone` | параметров корпуса (глубина, шаг, отступ, высота) в классификаторе нет |

Левая колонка 1.0 группирует эти `layer_id` в пять полок, без дерева на десятки
типов: Территория, Существующее, Ограничения, Проект, Оформление.
Внутри полки — видимость, захват, подпись класса, знак ЛГР если он есть.
Объект без кода класса или без знака (и без пользовательского override) попадает
в паспорт как дыра классификатора.

Новые коды классификатора (река, сервитут, сеть, существующее здание отдельно
от проектного) в этот черновик не добавляются. Их добавление — правка
`classifier_base.json` и тестов модели, отдельным коммитом, после согласия
по этой таблице.

## 5. Информационная архитектура

Одна оболочка. Вид переключается в одном месте. Клавиши `1` / `2` / `3`.

Холст занимает около трёх четвертей окна во всех трёх видах.
Панели контекстные. Постоянный лес вкладок беты не переносится.

### 5.1. Постоянный каркас

Слева узкая колонка «Слои»: полки из §4, видимость, захват, класс и знак.
Сверху лента по этапу работы, не по полному набору CAD:

`Файл` · `Участок` · `Анализ` · `Черчение` · `Концепция` · `ТЭП` · `Листы` · `Выпуск`

Справа инспектор выбранного. Вкладки инспектора появляются по контексту,
одновременно видна одна:

- свойства объекта;
- роль слоя (`layer_id`, класс, стадия, знак);
- происхождение (источник, дата, документ, `grado_key`);
- предпроверка;
- зависимости концепции (вид Чертёж и вид Карта на проектных слоях).

Снизу статус: СК `UTM 37N`, масштаб `1:N`, шаг привязки в метрах, орто
включено или выключено, число несохранённых дельт, имя файла.

Командная строка под статусом. Подсказка привязки — человеческая:
«Привязка к концу», «Привязка к пересечению», «Привязка к середине»,
«Ближайшая точка». Имена `snapEndpoint` в интерфейс не выводятся.

Пустое состояние каждого вида — одно предложение, что сделать следующим шагом.
Ошибка HTTP в журнале сервера — только ASCII. В интерфейсе — короткая русская фраза.

### 5.2. Три вида

**Карта (`1`).** Контекст участка. Подложки OSM, Sentinel-2, рельеф.
Импорт и разбор слоёв анализа. ЗОУИТ и документы. Паспорт участка открывается
отсюда и не становится четвёртым видом.

**Чертёж (`2`).** Привязки, орто, размеры, команды §6, знаки ЛГР, роли слоёв.
Подложка можно приглушить. Размеры живут на слое оформления и в модель ГИС
не притворяются объектами классификатора: сегодня они и так исключены из
предпроверки экспорта.

**Альбом (`3`).** Листы, рамка, легенда из знаков, которые реально стоят на
листе (`StyleSet.legend_entries`), живая таблица ТЭП, выпуск.
Масштаб листа обязателен. Лист без масштаба не выпускается.

### 5.3. Лента

| Группа | Действия, которые уже на чём-то стоят | Действия 1.0 без функции ядра |
|---|---|---|
| Файл | новый, открыть `.grado`, сохранить, автосейв | — |
| Участок | нарисовать границу (`terr.boundary`), импорт SHP/GeoJSON участка, кадастр через НСПД | — |
| Анализ | НСПД, OSM, рельеф-подложка, Sentinel-подложка, ZIP ГИС ОГД, каталог ФГИС ТП по УИН, паспорт | bbox-фильтр ФГИС ТП по границе |
| Черчение | точка, полилиния, полигон, дуга 3 точки, окружность, сопряжение через `Path.fillet_polyline`, офсет и пикетаж красной линии | trim, extend, join, поворот, масштаб, зеркало — в ядре нет; привязка ко всем операциям — после индекса |
| Концепция | функциональная зона, пятно `pp.placement_zone`, ось УДС, соцобъект точкой | параметры корпуса и флаг ручной правки |

`data.mos.ru` в ленте отсутствует.

### 5.4. Мастер первого запуска

Отдельное приложение `apps/wizard` в 1.0 не показывается. Его сценарий
становится первым проходом оболочки. Логика `TerritoryWizard`
(граница → проект → движок → пять листов) остаётся эталоном состава, не эталоном окна.

- Шаг A. Граница: нарисовать / SHP / кадастровый номер через НСПД.
  Слой `project.territory.boundary` создаётся сразу.
- Шаг B. Какие источники подтянуть. У каждого три состояния: нет / грузится / есть снимок и дата.
- Шаг C. Профиль норм: `moscow_krt`. Зона образования 1 или 2 и режим территории
  2152-ПП выбираются здесь. Это параметры, не геометрия.
- Шаг D. Рабочий стол на виде Карта. Слои, которые пришли, разложены по полкам.
  Паспорт открыт, если что-то не загрузилось.

Пустой отказ шага B не блокирует стол: паспорт пишет, чего нет.

### 5.5. Состояние приложения

Один store. Состав: проект (открытый `.grado` или пустой буфер до первой записи),
выбор, инструмент, вид `map|draw|album`, снимок коннекторов
(нет / грузится / манифест), dirty-счётчик дельт, орто, шаг привязки, масштаб вида.
Геометрия, ТЭП, импорт, PDF и DXF считаются на сервере вызовом `core/*`.
Холст хранит тесселяцию для рисования и не является вторым source of truth.

Порядок скриптов беты не копировать. Старые `app-transform.js`, `app-snap.js`,
`app-data.js`, `app-style-ui.js`, `app-attr.js`, `app-import.js`, `collab.js`
читать как описание поведения, когда дойдёт очередь черчения и совместной работы.

## 6. Командная строка

Девять коротких имён из брифа. Английское имя — то, которым команда вызывается
второй раз. Полное русское слово тоже принимается. Новые короткие имена здесь
не вводятся: сопряжение, поворот и масштаб вводятся словами, пока не согласован
отдельный псевдоним.

| Ввод | Действие | Опора в коде сегодня | Готово для 1.0 |
|---|---|---|---|
| `пл` / `pl` | полилиния | `Path.polyline`, LineString | да, после общего snap-индекса |
| `отр` / `l` | отрезок из двух точек | LineString | да, после индекса |
| `плг` / `pg` | полигон | Polygon | да, после индекса |
| `дга` / `a` | дуга по трём точкам | `Arc.from_3pts` | рисовать можно; запись параметрики в `geom` — нет |
| `кр` / `c` | окружность | JSON `circle`, `make_buffer` для точки | та же дыра записи |
| `обр` / `tr` | обрезать | нет | после 1.0, команды в ленте нет |
| `удл` / `ex` | удлинить | нет | после 1.0, команды в ленте нет |
| `соед` / `j` | соединить | нет | после 1.0, команды в ленте нет |
| `зрк` / `mi` | зеркало | `grado_geom.affine.mirror` | да, как аффинное преобразование точек |
| `сопряжение` | скругление вершины | `Path.fillet_polyline` | радиус хранится схемой `path` в колонке `curve` |
| `поворот`, `масштаб` | трансформация | `affine.rotate`, `affine.scale` | да |
| орто | ограничение угла | состояние вида | да как режим, не как геометрия |
| привязка | конец, пересечение, середина, ближайшая | `Snapper` с сеткой клеток | да для отрезков. Дуги в индекс не входят. Этого хватает для 1.0 |

Точка ставится инструментом ленты «точка» и полным словом `точка`.
Короткого псевдонима в брифе для неё нет.

Размер — команда `размер`. В DXF он может уйти слоем `RAZMERY`
(`annot.dim` в `dxf_export.py`). В классификаторе такого кода нет.
Либо завести класс аннотации, либо оставить размер вне GPKG и писать его
только в DXF/PDF. До выбора предпроверка продолжает не требовать размер как объект ГИС.

## 7. Анализ и паспорт участка

Панель «Анализ» на виде Карта. Карточка источника: нет / грузится / снимок и дата
(`SnapshotStore.manifest`). Повторный сдвиг карты не зовёт Overpass, пока bbox
покрыт последним снимком этого источника.

Паспорт — экран поверх карты. Поля, которые собираются из уже существующих
структур, и поля, которых ещё нет:

| Блок паспорта | Откуда брать сейчас | Что добавить |
|---|---|---|
| Что загрузилось | манифесты `sources_journal`, группы `fetch_extent` | дата и имя источника на карточке |
| Чего нет | источник в состоянии «нет» или строка `notes` | явный список запрошенных и пустых |
| ЗОУИТ ∩ граница | геометрия `terr.restrict` / слоёв ЗОУИТ и `terr_area` | пересечение полигонов в ядре; сегодня есть только клип «центроид внутри границы» для ТЭП |
| Документы ФГИС ТП в bbox | каталог отдаёт `stp_extent`, фильтр не применяется | грубый отбор по bbox границы на сервере |
| Дыры классификатора | объект без маршрута в `preflight` (`unrouted_features`) | плюс объект без знака ЛГР и без override |
| Безымянная ЗОУИТ | имя может отсутствовать | подпись «ЗОУИТ без имени / УИН» |

Кадастровый номер на шаге A ищет участок через `NspdDirect` (категория 36368)
или через уже лежащий захват `NspdCapture`. Логин не спрашивать.

ГИС ОГД: пользователь кладёт ZIP или SHP. Координаты МСК-50 переводятся
`msk50_to_wgs84`, затем `wgs84_to_utm37n`. В паспорте строка калибровки:
«МСК-50 → UTM 37N». Другая зона — ошибка импорта «калибровка 1.0 этой зоны не
делает», а не молчаливый сдвиг.

## 8. ТЭП

Считает только `Engine` из пресета `moscow_krt.json`.
Площади `terr_area` и `restrict_area` приходят из геометрии
(`collect_inputs` / `_role_areas`) и только внутри границы.
Факт СПП в `compute_tep` — сумма `building_footprint` × этажность.
Нормативные входы, которые геометрия не содержит (`density`, `ratio_zh`,
`percent_vpp`, `education_zone`, `territory_mode`, `k_rail`, `k_ba`),
задаются в инспекторе как параметры профиля. Пользователь видит число, которое
сам оставил.

В файле пресета у `terr_area` по-прежнему записан default 15, у движка он
нужен, чтобы выражение вообще имело число. `compute_tep` это число не отдаёт,
если на чертеже нет роли `terr_area`: `inputs.terr_area` равен `null`,
значения метрик равны `null`, альбом через `album_engine` печатает «н/д».
Нулевая площадь настоящей границы остаётся нулём и не подменяется 15.
Этажность вне 1…75 и пустое поле не становятся 9: такое здание увеличивает
`fact.floors_unknown` и не входит в факт СПП. В файл `.grado` девятка тоже
не пишется.

Проверки, которые движок уже честно не закрывает и помечает как требующие данных
участка: плотность против ПЗЗ/ГПЗУ, транспорт 945-ПП, территориальная доступность
и радиусы обслуживания. В таблице они остаются текстом «требуется проверка».
Зелёную галочку на них не ставить: `compute_tep` для плотности и транспорта
уже отдаёт `ok: false`.

Процент озеленения из нарисованных газонов ядро не считает. Метрика
`green_area_required` — норматив от населения или от доли режима реконструкции.
Пока нет слоя озеленения с ролью, факт озеленения — «н/д», норматив можно
показать отдельно, если заданы граница и режим территории.

## 9. Зависимости концепции

Линейная цепочка в инспекторе. Не больше десяти узлов. Произвольного скрипта нет.
Каждый узел — готовые поля.

```
Граница (terr_area)
  → офсеты ограничений (ЗОУИТ, отступ)
    → допустимое пятно
      → корпуса (прямоугольник или гребёнка)
        → дворы и проезды
          → ТЭП
            → легенда и лист
```

Что из этого уже является функцией:

| Узел | Функция сегодня | Статус узла 1.0 |
|---|---|---|
| Граница | слой `terr.boundary`, клип `_clip_to_territory` | есть |
| Офсет | `Path.offset`, `redline_offset`, `make_buffer` | есть как операция над линией и точкой; вычитания ЗОУИТ из границы нет |
| Допустимое пятно | нет | новый расчёт на `core/geom` |
| Корпуса | нет | новый узел; класс `oks.building` хранит только контур, этажность, назначение |
| Дворы и проезды | нет | новый узел |
| ТЭП | `TepLink` + `Engine` | есть, после правила «н/д» |
| Легенда и лист | `legend_entries`, `make_album` | есть для пяти живых листов |

Поля, которые бриф хочет на объектах и которых в классификаторе нет:
у зоны — целевая плотность, доля озеленения, этажность, места ДОО/школ;
у пятна — глубина корпуса, шаг секции, отступ от красной линии, высота.
Их хранить атрибутами слоя концепции, не вторым калькулятором.
Пока атрибута нет, узел показывает «н/д» и не выдумывает корпус.

Ручка «отступ 10 м» пересчитывает пятно и ТЭП только если пятно не помечено
«перебито вручную». Флага в модели нет: это новое поле объекта или узла.
Правка контура рукой ставит флаг и останавливает перезапись этого узла.
Сломанное сопряжение (`PathError`, потеря параметров дуги при сохранении)
блокирует пересчёт цепочки.

Покрытие ДОО и школ в 1.0 нет. Отдельной ячейки «покрыто / не покрыто» нет.
`make_buffer` остаётся черчением окружности. Норматив мест ДОО и школ по
2151-ПП по-прежнему считается из населения, когда задана граница. Радиусы
обслуживания `compute_tep` не проверяет и галочку на них не ставит.

## 10. Выпуск

Кнопка PDF, альбома и DXF сначала вызывает предпроверку.
`can_export` сегодня ложен только при ошибках маршрута и битой геометрии.

Правило 1.0. Ошибка, выпуск закрыт:

- нет объекта роли `terr_area`, а цель — ТЭП, альбом с таблицей ТЭП или лист ТЭП;
- слой без `layer_id` из реестра проекта;
- кривая без параметров, в файле только схлопнутая ломаная;
- импорт МСК не из пары UTM 37N ↔ МСК-50;
- лист без масштаба.

Предупреждение, выпуск можно подтвердить:

- объект снаружи границы (представительная точка вне `terr_area`);
- знак не из библиотеки ЛГР и не из `style_overrides`;
- повтор идентификаторов;
- очень большой проект.

Объекты вне границы сегодня в предпроверке не ищутся. Клип ТЭП их молча
выбрасывает из цифр. Паспорт и предпроверка должны их назвать.

Выходные файлы:

- PDF в масштабе листа, рамка `PageBorder`, штамп `StampFrame`, легенда по
  фактическим знакам;
- альбом из живых листов, которые пользователь отметил (для АГК минимум три:
  опорный план, схема, ТЭП — из уже существующих `base`, `apo`, `tep`);
- DXF R12;
- `.grado`.

На GitHub Pages этих четырёх кнопок нет.

## 11. Ограничения, которые интерфейс и README говорят вслух

- Калибровка МСК в 1.0 — только UTM 37N и МСК-50.
- У ФГИС ТП нет территориального каталога. Есть грубый фильтр bbox границы,
  и его ещё нет в `FgistpConnector.catalog`.
- `data.mos.ru` нет.
- Раскладка наложений подписей на чертеже — после 1.0. В 1.0 якорь и ручной сдвиг.
  Жадный фильтр `build_ops` остаётся поведением печати и не называется решателем.
- `grado_key` переживает круг `.grado`. Это закрыто колонкой, не маской в JS.
- Нодинг произвольных пересечений в 1.0 не делается. JS-нодинг по-прежнему запрещён.
- Параметры дуги, окружности и сопряжения лежат в колонке `curve`. Ломаная в
  `geom` — тесселяция для QGIS.
- ГИС ОГД для пользователя 1.0 — файл ZIP/SHP. REST `GisogdApi` в ядре есть и
  тестами покрыт; на ленту 1.0 он не выносится.
- Зоны обслуживания школ и ДОО ядро не считает.
- Листы «фотофиксация», «парковки», «озеленение» в `make_album` — заглушки.
- Дефолты 15 га и 9 этажей в выпуск не попадают: это дефект расчёта, он закрыт
  в `compute_tep` и в том движке, которым печатает альбом.

## 12. Порядок после принятия сверки

Таблица ролей §4 принята без новых кодов реки, сервитута и сети.
Trim, extend, join и нодинг в ленту 1.0 не ставятся.
Зеркало, поворот и масштаб — аффинные функции `core/geom`, не отдельные
команды обрезки.

Очередь кода, холст только после фикстуры:

1. Колонка `grado_key`. Круг `.grado` возвращает `srcKey`.
2. Честный ТЭП в `compute_tep` до альбома. Нет границы — «н/д», не 15 га.
   Нет этажности 1…75 — здание не множится на 9.
3. Схема кривой в колонке `curve` (`arc` / `circle` / `path`). Колонка `geom`
   — тесселяция для QGIS, не единственная копия параметров.
4. Сетка привязок и аффинные `rotate` / `scale` / `mirror`.
5. Фикстура `apps/studio/tests/fixtures/quarter.json`. Прогон из неё, не из
   живого `.grado`.
6. Каркас холста открыт по адресу `/v2/index.html`. Старый `index.html` остаётся
   входом беты. В каркасе есть три вида, полки слоёв, командная строка, честный
   ТЭП и выпуск PDF / альбома / `.grado`. Анализ данных и паспорт ещё без снимков.
   Автосейв каркас не включает.

`terrain` в `Project.SOURCES` по-прежнему нет. Рельеф остаётся подложкой и в
`.grado` не пишется.

Нижняя планка регрессии: studio 275, connectors 42, render 51.
Новые тесты добавляются сверху. Сажать эти три числа заменой утверждений нельзя.

Узкий HTTP, к которому сводится текущий сервер, когда до него дойдёт очередь:

| Контракт 1.0 | Уже есть |
|---|---|
| project | `/api/grado`, `/api/open-grado`, `/api/initial-grado` |
| edit-op | нет одного входа; правки приезжают пачкой features в `build_project` |
| compute-tep | `POST /api/tep` |
| connectors | `/api/import-nspd`, `/api/import-gisogd`, `/api/import-fgistp-doc`, `/api/fgistp-catalog`, `/api/fgistp-layers`, `/api/fetch-extent`, `/api/inbox` |
| layout | `POST /api/album`, `POST /api/print` |
| export | `/api/preflight`, `/api/dxf`, `/api/grado` |
| autosave | `/api/autosave`, `/api/autosave/backups` |

`edit-op` должен звать `Session`, а не пересобирать проект из всего холста.
Этого входа сегодня нет. Проектировать его вместе с пунктами 1–2, не раньше
согласия по ролям.

## 13. Готовность сценария

Градостроитель за один вечер, без чтения исходников: граница квартала, открытые
данные, существующие и проектные слои знаками ЛГР, ТЭП по `moscow_krt`, три листа
альбома, PDF + DXF + `.grado`, который QGIS открывает с теми же слоями.
Руками в таблицу ТЭП он не входит.

На 2026-09-22 модель, классификатор, пресет, коннекторы, пять листов, DXF, PDF,
журнал и знаки ЛГР уже были. После принятия сверки к ним добавлены колонка
`grado_key`, честный ТЭП, колонка `curve`, сетка привязок, аффинные преобразования
и фикстура квартала. Холст 1.0 не подключён.

В 1.0 сознательно нет кнопок: trim, extend, join, нодинг произвольных
пересечений, покрытие школ и ДОО, паспорт пересечений, bbox-фильтр ФГИС ТП,
узлы нарезки корпусов. Их отсутствие — граница версии, не открытый дефект расчёта.
