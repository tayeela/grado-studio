# Полноценная браузерная версия

Облачный режим запускает ту же ГРАДО Студию, что и настольный: доступны ТЭП,
PDF, DXF, альбомы, серверные импорты и совместная работа. Пользователю нужен
только современный браузер; Python и исходники на его компьютере не требуются.

GitHub Pages для этого недостаточно: он раздаёт только статические файлы и не
может выполнять серверные расчёты. Нужен сервер или облачная платформа с Docker,
HTTPS и постоянным диском.

## Быстрый запуск Docker

```sh
docker build -t grado-studio .
docker volume create grado-data
docker run --name grado-studio \
  -p 8080:8080 \
  -v grado-data:/data \
  grado-studio
```

Проверка состояния: `http://localhost:8080/api/health`. При первом запуске в
логах контейнера появляется одноразовый инвайт-код:

```sh
docker logs grado-studio
```

Первый зарегистрированный пользователь становится администратором и создаёт
инвайты для остальных.

## Требования к рабочему размещению

- публичный адрес только через HTTPS;
- постоянный диск подключён к `/data`;
- одна реплика приложения: файловое хранилище не рассчитано на несколько
  параллельных контейнеров;
- регулярная резервная копия всего каталога `/data`;
- логи первого запуска доступны только владельцу сервера.

Облачные платформы обычно сами завершают HTTPS и передают приложению переменную
`PORT`. Она поддерживается автоматически. Для собственного VPS поставьте перед
контейнером Caddy или nginx и не открывайте внутренний порт 8080 напрямую.

## Переменные окружения

| Переменная | Назначение | Значение в контейнере |
|---|---|---|
| `PORT` | внутренний HTTP-порт | `8080` |
| `GRADO_CLOUD` | безопасный облачный режим и авторизация | `1` |
| `GRADO_STUDIO_DATA_DIR` | проекты, пользователи, кэш и настройки | `/data` |
| `GRADO_HOST` | сетевой интерфейс | `0.0.0.0` |

В облачном режиме локальный мост на порту 8081 отключён. Импорт файлов выполняется
через интерфейс браузера; сервер не получает доступ к файлам компьютера
пользователя без явной загрузки. Импорт по локальному пути сервера и по URL
отключён; это защищает файловую систему и внутреннюю сеть хостинга.

## Обновление

Соберите новый образ, остановите старый контейнер и запустите новый с тем же
томом `/data`. Не удаляйте том: в нём находятся учётные записи, проекты,
автосохранения и пользовательские стили.
