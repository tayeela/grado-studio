# План 06.10.2026: вики, процесс, логика слоёв листов

Слово владельца (06.10.2026): «проверь вообще логику включения слоёв под каждый отдельный лист. Всё должно быть не по
предустановленному скрипту, а максимально гибко, но при этом под цели сбора. Создай вики по всему проекту, которая
будет исправляться автоматически при любой правке, уменьшит количество токенов ввода и даст всегда актуальную
информацию; автоматизируй и оптимизируй процессы, перепридумай всю схему работы, пиши себе хорошие промпты».

Порядок: вики → проверка и промпты → слои. Коммит после каждой части.

1. Вики `docs/wiki/` — генерируется `tools/wiki.py` (только stdlib, только файлы репозитория): INDEX, sources, sheets,
   api, modules, rules, tests, team, changelog-recent; вручную — architecture, recipes. `wiki.py --check` в проверке;
   pre-commit добавляет обновлённую вики (удобство; настоящая страховка — `--check`). Вики не вызывает выкладку.
2. `tools/gate.sh` — одна команда проверки; `docs/team/prompts/` — шаблоны заданий (implement, review, qa-real-check,
   audit, lead-cycle-start); CYCLE.md ссылается на них; RULE о начале цикла.
3. Слои листов: аудит (только чтение) → спецификация «роли листа» (`spec-T85-layer-roles.md`) → совет → невидимая часть
   (выбор источника по роли и покрытию) в ветке команды; видимая (переключатели ролей на листе) — владельцу А/Б/В.
   «Гибко» = гибкие источники и правки владельца, не новое содержание («ничего не придумывать сверх образцов»).
