# План T6 — резерв участков ДОО, школы, поликлиники (архитектор, 03.10.2026)

Решения владельца 03.10: 1В зона норм выбирается в «Нормативах» (по умолчанию из района; район не в списках —
зона 2 с пометкой); 2А свободные места — три числа вручную, по умолчанию 0; 3А ОВЗ не прибавлять; 4А встроенные
ДОО не резервировать; 5А школа — всегда один участок «не менее». Площади — минимум таблицы; СПП и плотность от
резерва не меняются. Спецификация и числа примера: `spec-T5-social-objects.md`, `core/compute/tests/test_social_fixture.py`.

## Что есть в коде
- ТЭП: `NTep.onExecute` → `tepRequest` (app.js ~984) → POST `/api/tep` (server.py ~2052, белый список полей ~2053) →
  `tep()` (server.py ~914) → `Engine` пресета `moscow_calc2.json` (население, потребность, `doo_count`, `*_plot_ha` —
  выражения пресета ~125–155) → `{metrics, density_total, constants_changed}`. Группы ТЭП — по `m.group`, порядок в
  `GROUP_ORDER` (app.js ~1494).
- Параметры проекта: `tepParams(node)` → `node.properties.tp` (едет в разделе `meta.graph` совместной работы);
  нормативы вручную — `tp.constants` (`norms.js`, `GET /api/tep/norms`). Зона: селектор «Образование» в «Показателях»
  (app.js ~1509) пишет `tp.zone` и `tp.auto=false` (замораживает ещё K1, K2, ТиНАО — для зоны так делать нельзя).
- `/api/place` = `place_info` (server.py ~1139) — поиск района, не посадка. Неизвестный район → зона 1 (строка ~1185).
- Посадка — только в браузере: `NPlace` (app.js ~894) → `generate(site,p)` (~1021) → `place()` (~1075); `site` —
  «Пятно застройки» (территория − ЗОУИТ − разрывы − отступы). Результат: `RESULT.sketch` (здания, `.plots`, `.streets`),
  `fillSketch` (~1373) рисует `plots/streets` в `groundSrc` цветами `GROUND` по `kind`; `bakeSketch` (~1442) сохраняет
  `plots` слоем «Эскиз: участки и дворы» (категории по «Вид»). Потребность известна только после ответа `/api/tep`,
  значит резерв считается после ТЭП и не меняет здания (СПП не трогается).

## Шаги
1. **Сервер: дефицит и участки в пресете (backend).** `moscow_calc2.json`: входы `free_doo`, `free_school`,
   `free_clinic` (inputs, не constants; 0, min 0, max 100000); группа метрик «Резерв участков»: `doo_deficit`,
   `doo_res_n = ceil(deficit/doo_plot_cap2)`, деление мест на n участков (q+1 первым), `doo_res_m2` по ярусу каждого
   участка (≤150 → 35, иначе 32), `school_deficit`, `school_res_m2` (ярус по дефициту), `clinic_deficit`,
   `clinic_res_m2 = clinic_plot_norm_ha·10000` при дефиците > 0, `social_res_m2/ha/share` (сумма в м², округление
   только на показе). `/api/tep`: запрос — три числа (белый список), ответ — поле `social: [{kind:"doo"|"school"|"clinic",
   places, m2}]` (ДОО n записей, q+1 первой; школа 0/1; поликлиника 0/1) — только числа. `place_info`: район не в
   списках → зона 2 с пометкой `zone_note`; известные районы (таблица 945-ПП) — как сейчас (зона 1 вне списка зоны 2).
   Проверка: unit через `tep()`: B0 ДОО [263, 262] = 8416 + 8384, школа 16 544, поликлиника 3500, итого 36 844 м² /
   3,684 га / 18,422 %; B1 (175/400/100) ДОО [350] = 11 200, школа 12 046, 3500, 26 746 / 2,675 / 13,373; A1 (зона 1,
   СПП 150, 40/100/20) 2905 + 2869 + 3500 = 9274 / 0,927 / 4,637; дефицит 0 → пустой список; свободных больше
   потребности → не отрицательно; отрицательное или NaN → 400. `reserve()` в `test_social_fixture.py` заменяется вызовом
   движка. `test_tep_norms_cover_all_constants` должен остаться зелёным (входы — не константы).
2. **«Нормативы» → блок «Условия проекта» (frontend).** `tp.free = {doo, school, clinic}` (по умолчанию 0), `tp.zoneSet`
   (bool) — в `node.properties.tp`, без миграции. `tepRequest` добавляет три числа. Зона: не трогать `tp.auto`; при
   `tp.zoneSet` `placeLookup` не перезаписывает `tp.zone`; показывать источник («по району X» / «зона 2 принята: район
   не в списках 2151-ПП»). Селектор в «Показателях» синхронен. Числа 0–100000, целые, тот же parse/debounce, `viewer()`
   отключает. «Вернуть все действующие» свободные места не трогает. «Резерв участков» в `GROUP_ORDER`. Проверка: E2E —
   ввод 175/400/100 даёт B1 в «Показателях»; после перезагрузки числа на месте; снимки 1280 светлая/тёмная.
3. **План в браузере без геометрии (frontend).** `tepRequest` копирует `r.social` в результат; радиусы: ДОО 300 м (ЦАО
   500), школа 1000 м (ЦАО — без радиуса), поликлиника — нет; `CAO(tp.okrug)` из analysis.js; SERVICES analysis.js не
   трогать. Строка «Резерв: ДОО n, школа 1, поликлиника 1 · X,XXX га (YY %)» над метриками.
4. **Геометрия резерва (frontend, последний).** `reserveSocial(site, sketch, social, radii)`: free = site ∖ buf(здания,
   gap) ∖ streets ∖ plots; части `splitParts`; порядок школа, ДОО, поликлиника; прямоугольник точной площади ~1,5:1
   вдоль `partFrame`, скольжение от угла, ближнего к домам; принять при `fits()` (допуск 0,997) и расстоянии до
   ближайшего дома ≤ радиуса; вычесть из free. Не помещается — на карту ничего, `note` «ДОО №1 (0,842 га) не помещается
   в свободной земле пятна — освободите землю» + строка-предупреждение в «Резерв участков»; участок не уменьшать.
   Вывод — в `sketch.plots` с `kind` «участок ДОО» / «участок школы» / «участок поликлиники», `m2`, «Места», «Дефицит»;
   цвета в `GROUND` и в `cat.colors` `bakeSketch`; здания не трогать; считать в `.then` NTep или в `recompute` при
   смене `_tep`, кэш `gid(site)+gid(sketch)+JSON(social)`; после «Сохранить слоем» превью не дублировать. Проверка: E2E
   на примере B — 3 участка нужных площадей (±0,3 %), внутри пятна, вне зданий, в радиусе; СПП и плотность те же.

## Решено руководителем по вопросам архитектора (внутреннее, владельца не спрашиваем)
Q1 известные районы — зона 1 как сейчас, зона 2 с пометкой только для неизвестных. Q3 радиусы — константы в клиенте.
Q4 SERVICES не трогать. Q5 `density_mkd_plots`, баланс, озеленение — без изменений, только показ. Q6 — пометка в
эскизе плюс строка-предупреждение. Q2 подписи — пишет исполнитель шага 2 по §1 спецификации, креативный директор
смотрит снимок. Риск: пятно часто занято домами целиком — тогда «не помещается»; вариант «сначала резерв, потом дома»
снижает СПП и требует решения владельца (не в T6).
