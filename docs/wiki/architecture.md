# Как устроен ГРАДО 2 (пишется вручную; править при смене устройства)

Рабочая программа — **ГРАДО 2** (`apps/grado2`). Старая студия (`apps/studio`), мастер и calc-web закрыты; их код
остаётся только ради тестов ядра. Прежний `docs/archive/studio/architecture.md` описывает старую студию и устарел.

## Части

- **Сервер** `apps/grado2/server.py` — один процесс Python без внешних зависимостей сверх `requirements.txt`.
  Раздаёт страницу (`web/`), выгружает данные с порталов (`/api/fetch` → коннекторы ядра), считает ТЭП, печатает
  (`/api/print/pdf|pptx|svg`), хранит проекты (`/api/project`, папка проектов). Режим «хаб» (`hub.py`) — совместная
  работа на сайте grado.tailink.tech. Маршруты — api.md.
- **Коннекторы** `core/connectors/grado_connectors` — ГИС ОГД (`gisogd_api.py`: слой целиком в кэш, срез по рамке),
  ЕГКО (та же схема, карта base2), НСПД, OSM (Overpass), Яндекс (векторные плитки `yandex_vmap.py`), ФГИС ТП. Кэш на
  диске `~/.grado2/cache/<портал>`. Повторы и паузы живут здесь и в выгрузках сервера (`server.py`, `sat_io.py`, `ogd_all.py`). Источники по ключам — sources.md.
- **Страница** `apps/grado2/web` — OpenLayers + turf, без сборки. `app.js` (карта, территория, поиск, данные),
  `layers.js` (слои, стили, «Свойства»), `cad.js` (черчение), `sheets.js` (листы, альбом, выгрузки), `albums.js`
  (альбом ППТ КРТ: шаблоны листов `PPTKRT_C` и `PPTKRT_D`, порядок выдачи `PPTKRT_ORDER`, выбор источников — `conceptSheet`), малые модули с чистыми функциями (`labelfmt.js`, `roadsrc.js`,
  `roadclean.js`, `railstations.js`, `gpzones.js`, `albummeta.js`). Модули — modules.md.
- **Печать** `apps/grado2/print_io.py` (карта листа `SketchMapFrame`: подложка, слои, маска, подписи без наложений,
  знаки ЛГР), `album_io.py` (оформление шаблона ППТ КРТ, легенда, угловые надписи), бэкенды
  `core/render/grado_render` (PDF, SVG, PPTX — одни и те же операции рисования).

## Данные альбома: путь от портала до листа

1. Территория (граница) — файл, участки по кадастровым номерам, номер КРТ в поиске, рисование.
2. «Собрать альбом ППТ КРТ» (`buildAlbum` → `buildSection0`): по ключам листов считает рамки, качает нужные слои
   (одна выгрузка на одинаковую рамку; Яндекс — не больше 40 км² вокруг территории), строит производные слои.
3. `albumSpec` → для каждого листа `sheetSpec` берёт слои по `keys`, стилю и `only`, затем `conceptSheet` (albums.js)
   выбирает источники по данным рамки (дороги, станции, районы, зоны Генплана), собирает легенду.
4. Сервер печатает спецификацию: `print_io` + `album_io` → PDF/PPTX.

## Правила, которые нельзя забывать

- Правила оформления владельца — `docs/standards/albums/label-rules.md` (rules.md — указатель). Ничего не придумывать
  сверх образцов; новое замечание — сначала в правила, потом в код.
- Координаты: МСК (как в QGIS) и система ГИС ОГД; всё показываемое — МСК (CLAUDE.md, железное правило 3).
- Проект владельца не трогать; тесты — только на тестовых копиях (recipes.md).

## Сайт и автоматика

- Сайт grado.tailink.tech — та же программа в совместном режиме (`server.py --hub`) на сервере `msk` (службы `grado` и `grado-guest`);
  выкладывает его сам сервер: таймер `grado-pull` раз в 5 минут забирает `main` с GitHub (`tools/server_pull/README.md`).
- GitHub Actions (`.github/workflows/README.md`): `grado2-release.yml` — модульные и браузерные тесты на PR, которые меняют `apps/grado2`, `core` или `packaging/grado2*`, и сборка установщиков по тегу и вручную;
  `docs.yml` — навигация документов и свежесть вики; `wiki.yml` — пересборка вики и копия в `tayeela/grado-wiki`.
- Где что читать дальше: карта папок — `INDEX.md`, карта документов — `docs/INDEX.md`, соглашения по коду — `conventions.md`.
