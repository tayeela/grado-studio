# План разработки до полной рабочей версии (1.0)

Текущее состояние: 7 модулей ядра + мастер территории + браузерная студия,
137 тестов. Дальше — доведение Python-версии до инструмента, которым
делается реальная АГК от исходных данных до альбома. C++ ядро — после 1.0.
Каждый этап заканчивается рабочим приращением, которое можно пробовать.

## Этап 0 — бета-стабилизация студии (1–2 недели)

Цикл: пользователь рисует реальную задачу → баг/затык → правка.
- баг-репорты: баннер ошибок уже на экране, текст присылать как есть;
- редактирование: добавление/удаление вершин на ребре, произвольный контур
  здания (не только прямоугольник), поворот, копирование объектов;
- ввод размеров с клавиатуры (длина/площадь при рисовании), орто-режим;
- панель слоёв: видимость/блокировка;
- сохранение/открытие проекта файлом (.grado туда и обратно), не только
  автосейв в браузере.

Критерий готовности: концепция знакомой территории рисуется без «этого
нельзя сделать».

## Этап 1 — данные под чертежом (2–4 недели)

- ~~открытие .grado в студии (round-trip с QGIS)~~ — готово;
- ~~приём НСПД/ФГИС ТП напрямую от браузерного расширения~~ — готово (порт 8081);
- ~~подложка: XYZ-тайлы под холстом~~ — готово (OSM, прокси+кэш, локальная
  касательная плоскость для перевода метров чертежа в lon/lat);
- импорт ОГД-ZIP (через ogr2ogr, коннектор готов, не подключён к студии);
- фиксация снимков источников в проекте (провенанс уже в модели, снимки
  коннекторов существуют в connectors — не связаны со студией).

Критерий: опорный план реальной территории собирается в студии из
НСПД + ФГИС ТП + ОГД за час.

## Этап 2 — черчение до CAD-уровня (4–6 недель)

- дуги как объекты чертежа (по трём точкам), сопряжения на любых линиях;
- офсеты красных линий, пикетаж с подписями;
- функциональные зоны как топологическое покрытие (общая граница одна,
  ядро coverage готово) — баланс территории без дырок и нахлёстов;
- штриховки ЗОУИТ, размерные линии, направляющие;
- экспорт DXF (послойно), печать чертежа в масштабе в PDF.

Критерий: схема АПО целиком чертится в студии; DXF открывается в
nanoCAD/AutoCAD без потерь по слоям.

## Этап 3 — альбом полностью (3–4 недели)

- растровые вставки в PDF-писатель (JPEG) → листы «Ортофотоплан» и
  «Фотофиксация», подложка на карто-листах;
- листы «Соцобъекты», «Парковки», «Озеленение» (данные уже в движке),
  «ГПЗУ/ППТ» (реестры документов);
- редактор состава альбома (порядок/набор листов, шаблоны в JSON);
- титул: логотип-картинка, реквизиты организации.

Критерий: альбом уровня референса (13 листов) отдаётся заказчику без
InDesign.

## Этап 4 — проект и варианты (3–4 недели)

- сервер студии работает поверх открытого .grado с журналом reactive:
  сквозной undo, автосейв в файл, история;
- ветки вариантов концепции в UI, сравнение ТЭП вариантов рядом.

Критерий: один файл проекта — единственный источник истины; вариант Б
создаётся и сравнивается кнопкой.

## Этап 5 — упаковка в приложение (2–3 недели)

- одно приложение для macOS (py2app/Tauri-обёртка): иконка, меню,
  ассоциация файлов .grado, запуск без терминала;
- расширение браузера шлёт данные в студию из коробки.

Критерий: «скачал — открыл — работает» на чистом Mac.

## Этап 6 — расчёты и нормоконтроль (параллельно, 2–3 недели)

- пресеты ТЭП для МО и других регионов, редактор пресетов в UI;
- первые проверки rule engine: радиусы доступности ДОО/школ кругами на
  холсте, баланс зон, предельная плотность;
- сверка констант московского пресета с действующей МНГП.

Критерий: подбор плотности под норматив происходит в студии, а не в Excel.

## Итого

~4–5 месяцев такими же итерациями до 1.0. Порядок этапов 1–3 можно
менять под реальные задачи; этап 0 — немедленно, по обратной связи.

## После 1.0 (трек «большой версии»)

C++ ядро по готовым Python-эталонам (geom → render → reactive), GPU-холст,
PostGIS-совместная работа, XML-выгрузки ГИСОГД, клотоиды и нодинг
произвольных пересечений, label engine с разрешением коллизий.
