# Выкладка сайта самим сервером (таймер grado-pull на msk)

С 08.10.2026 (задача #73, вариант Б владельца) сайт grado.tailink.tech обновляет сам сервер `msk`, а не Mac владельца.
Раз в 5 минут сервер забирает ветку `main` с GitHub и, если в ней поменялась программа (`apps/grado2`, `core`,
`docs/standards`), ставит её на сайт. Слияние PR `team/t60 → main` на GitHub — это и есть выкладка; `git pull` на Mac сайт не трогает.

## Что делает каждый запуск (`grado-pull.sh`)

1. Берёт последний коммит `main` с GitHub ключом, у которого есть только чтение и только этого репозитория.
2. Программа не менялась с прошлой выкладки (правились только документы) — ничего не делает.
3. Сервер занят выгрузкой слоя или «DXF ГИС ОГД» — не перезапускает, пробует через 5 минут.
4. Кладёт код рядом с работающей версией, при новых зависимостях ставит их, переключает каталог, перезапускает `grado` и `grado-guest`.
5. Ждёт до 20 секунд, что `/api/health` ответит новой версией. Не ответила — возвращает прежнюю, и этот же код больше не пробует
   (сайт не перезапускается каждые 5 минут); следующий коммит в `main` с программой выкладывается как обычно.

Журнал: `journalctl -u grado-pull -n 30`. Последний выложенный коммит: `/opt/grado/pull/deployed.rev`.
Неудачный код: файл `/opt/grado/pull/failed` (удалить — таймер попробует его снова).

## Файлы

| файл | где на msk | что это |
|---|---|---|
| `grado-pull.sh` | `/opt/grado/bin/grado-pull.sh` | одна проверка и выкладка; `--mark-current` — запомнить `main` как выложенный без перезапуска |
| `grado-pull.service` | `/etc/systemd/system/` | служба, один запуск скрипта |
| `grado-pull.timer` | `/etc/systemd/system/` | таймер: раз в 5 минут, первый раз через 2 минуты после загрузки |
| `install-on-msk.sh` | — | установка; повторяемая, перед заменой файла кладёт копию `.bak-gradopull-<время>` |

Ключ и копия репозитория — `/opt/grado/pull/` (права 700). В GitHub никаких ключей от сервера нет, входящий доступ на msk не нужен.

## Установка (по процедуре taiLink: план, резервная копия, ЛОГ)

На самом msk под root запустить `install-on-msk.sh` (до слияния этой ветки в `main` — с `GRADO_PULL_REF=task/73-deploy`):

1. Первый запуск создаёт ключ, печатает его открытую часть и останавливается.
2. Ключ добавить в GitHub: `tayeela/grado-studio` → Settings → Deploy keys → Add, галочку «Allow write access» не ставить.
3. Второй запуск сверяет отпечаток github.com, кладёт скрипт и службы, отмечает текущую версию сайта и включает таймер.

Таймер надо включить **до** того, как эта ветка попадёт в `main`: после неё Mac больше не выкладывает.

## Откат

`systemctl disable --now grado-pull.timer` — сервер перестаёт сам выкладывать; сайт работает на той версии, что стоит.
Вернуть выкладку с Mac — откатить PR задачи #73 (в нём удалён прежний скрипт выкладки с Mac deploy-server.sh).

## Ночной прогрев кэша ГИС ОГД (таймер grado-warm)

На msk стоит второй таймер: каждую ночь в 00:30 UTC (03:30 МСК) `apps/grado2/ogd_warm.py` заново скачивает слои ГИС ОГД старше 6 дней,
по одному и с паузой; пока сайт сам качает слой, прогрев ждёт. Копия служб — `grado-warm.service` и `grado-warm.timer` рядом
(сняты с сервера 10.10.2026, задача #51). `install-on-msk.sh` их не ставит: они стояли раньше. Проверка:
`ssh msk 'systemctl list-timers grado-warm.timer'`; лог — `ssh msk 'journalctl -u grado-warm -n 50'`.
